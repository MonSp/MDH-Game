# 太古纪元：高阶NPC的LLM智能规划系统设计

## 设计理念：天道有灵，仙凡有别

在修仙世界中，低阶修士如过江之鲫，终日为生存奔波；而高阶修士与掌权者则需谋定而后动，其决策影响深远，非简单的行为树所能涵盖。引入大语言模型（LLM），正是为这些“有灵智”的NPC赋予真正的战略思考能力——他们不再是被动响应环境的棋子，而是能够主动规划、运筹帷幄的棋手。

**核心原则**：
- **分层调用**：仅境界≥金丹期，或职位≥家族长老的NPC启用LLM规划。
- **低频触发**：LLM规划以“游戏日”为最小单位，生成跨度1天至1年的宏观计划，日常执行仍由行为树负责。
- **输出结构化**：LLM输出必须为可被游戏引擎解析的JSON指令，与现有行为树无缝衔接。

---

## 1. LLM适用对象分级

| 层级 | 适用条件 | 调用频率 | 规划跨度 | 典型角色 |
|:---|:---|:---|:---|:---|
| **T0（天道级）** | 皇族家主、太虚境以上统一王朝的君主 | 游戏月/次 | 1个月 - 1年 | 秦国皇帝、太虚境霸主 |
| **T1（战略级）** | 一级家族家主、国战统帅、化神期散修 | 游戏周/次 | 1周 - 1个月 | 家族族长、大将军 |
| **T2（战术级）** | 二级/三级家族家主、元婴期长老、金丹期核心子弟 | 游戏日/次 | 1天 - 1周 | 小家族家主、传功长老 |
| **T3（行为树）** | 其余所有NPC | 不调用LLM | 实时 | 支脉子弟、仆从、练气修士 |

**动态升级**：若某NPC在行为树运行中触发重大事件（如家族被灭、获得至宝），可临时提升其LLM调用优先级，立即生成应对计划。

```text
│                      ▼                                      │
│            ┌───────────────────┐                            │
│            │   计划存储与更新  │                            │
│            │ (NPC.LLM_Plan)    │                            │

│            ┌───────────────────┐                            │
│            │   日常执行器      │                            │
│            │ 每帧/每秒检查当前 │                            │
│            │ 任务，调用行为树  │                            │

│            └───────────────────┘                            │
└─────────────────────────────────────────────────────────────┘
```

**关键点**：
- LLM生成的是**计划（Plan）**，行为树负责**执行（Execute）**。
- 计划以结构化JSON存储于NPC数据中，包含目标、子任务、时间节点、优先级。
- 当计划执行完毕或被突发事件打断时，触发LLM重新规划。

## 4. 计划执行与行为树交互

### 4.1 计划存储与状态更新

NPC实体新增字段：
```javascript
NPC.LLM_Plan = {
    plan_id: "PLAN_QIN_20250420_001",
    generated_at: "Day 120",
    expires_at: "Day 127",
    tasks: [...], // 上述sub_tasks数组
    current_task_index: 0,
    status: "ACTIVE" // ACTIVE, COMPLETED, INTERRUPTED, FAILED
}
```

### 4.2 日常执行器逻辑（每游戏小时检查）

```python
def update_npc_llm_plan(npc):
    plan = npc.LLM_Plan
    if plan is None or plan.status != "ACTIVE":
        return
    
    current_task = plan.tasks[plan.current_task_index]
    
    # 检查任务是否已完成
    if check_task_completion(npc, current_task):
        plan.current_task_index += 1
        if plan.current_task_index >= len(plan.tasks):
            plan.status = "COMPLETED"
            # 触发LLM生成下一周期计划（若仍在资格范围内）
            schedule_llm_planning(npc, next_horizon="1周")
        return
    
    # 检查任务是否超时
    if current_day > current_task.target_completion_day:
        handle_task_timeout(npc, current_task)  # 可能标记失败或请求重新规划
    
    # 将LLM任务转化为行为树可执行的动作
    bt_action = translate_llm_task_to_bt(current_task)
    if bt_action:
        inject_into_behavior_tree(npc, bt_action, priority=2)  # 优先级2为家族职责层
```

### 4.3 LLM任务到行为树动作的映射表

| LLM action_type | 对应行为树节点 | 注入位置 |
|:---|:---|:---|
| `ISSUE_ORDER` | 向指定NPC发送指令，修改其行为树优先级 | 目标NPC的优先级2 |
| `DIPLOMACY` | 触发外交事件，修改家族间好感度目标值 | 世界状态层 |
| `CULTIVATE` | 强制NPC进入“闭关修炼”状态，屏蔽其他行为 | 最高优先级，覆盖优先级1 |
| `INTELLIGENCE` | 生成情报收集任务，挂载到情报系统 | 后台情报池 |
| `RESOURCE_ALLOCATION` | 修改家族库房的资源分配权重 | 家族经济系统 |
| `MOBILIZE` | 批量修改家族内NPC的状态为“战争动员” | 家族军事系统 |
| `ASSASSINATE` | 生成针对特定目标的暗杀任务，分配给死士NPC | 目标NPC的生存应急子树 |

## 5. 突发事件与计划中断机制

### 5.1 触发重新规划的阈值条件

| 事件类型 | 严重程度 | 是否中断LLM计划 | 响应方式 |
|:---|:---|:---|:---|
| 家主遇刺 | 致命 | ✅ 立即中断 | 强制LLM紧急规划（1小时响应） |
| 家族被宣战 | 高 | ✅ 立即中断 | 强制LLM重新规划 |
| 国库资源低于警戒线20% | 高 | ✅ 立即中断 | 强制LLM重新规划 |
| 计划目标人物死亡 | 中 | ✅ 中断对应任务 | 仅调整当前计划 |
| 天降异宝（可争夺） | 中 | ❌ 不中断 | 作为高优先级临时任务插入 |
| 玩家挑衅/攻击 | 低 | ❌ 不中断 | 由行为树优先级1直接响应 |

### 5.2 紧急规划模式

当触发致命/高严重度事件时，系统调用LLM的`EMERGENCY`模式：
- **响应时间要求**：5分钟内生成计划（可调用更快的轻量模型）。
- **规划跨度**：1-3天，聚焦于生存与反击。
- **输出简化**：仅返回3个以内核心任务。

**紧急规划Prompt追加**：
```
【紧急状态】
当前发生突发事件：{event_description}
请忽略原有长期计划，以“保障自身与家族核心成员生存”为首要目标，生成一个3天内的紧急应对计划。
```

## 6. 多NPC计划的冲突检测与协调

### 6.1 计划冲突类型

| 冲突类型 | 示例 | 检测方式 | 解决策略 |
|:---|:---|:---|:---|
| **资源竞争** | 两个长老都计划使用家族唯一的凝婴丹 | 检查计划中的`use_resources`字段 | 按职位/修为优先级裁决 |
| **目标冲突** | 家主计划拉拢魏国，长老计划劫掠魏国商队 | 检查外交目标的一致性 | 家主权重大于长老，否决长老计划 |
| **空间冲突** | 两人计划同一时间使用同一间密室 | 检查`location`和`duration_days` | 按职位排队，或LLM生成时考虑资源占用表 |

### 6.2 家族级计划协调流程

```text
家主生成LLM计划（周/月）
        │
        ▼
计划下发至长老会（系统通知）
        │
        ├──► 长老生成LLM计划时，必须读取家主的计划摘要
        │     （作为输入context的一部分）
        │
        ├──► 长老计划提交后，系统进行冲突检测
        │     │
        │     ├─ 无冲突 ──► 批准执行
        │     │
        │     └─ 有冲突 ──► 返回修改建议，触发长老LLM重新规划
        │                    （若连续3次冲突，强制采用家主指令）
        │
        ▼
核心子弟生成计划时，读取直属长老的计划摘要
（以此类推，形成树状规划体系）
```

## 7. 性能与成本控制策略

### 7.1 调用频次估算与控制

| 层级 | 每区服适用数量 | 调用频率 | 日调用量估算（单区服） |
|:---|:---|:---|:---|
| T0 | ≤10人 | 月/次 | 0.3次/天 |
| T1 | ≤50人 | 周/次 | 7次/天 |
| T2 | ≤200人 | 日/次 | 200次/天 |
| **合计** | **≤260人** | - | **约207次/天** |

**成本控制措施**：
1. **缓存复用**：相同国家/家族的T1、T2 NPC，若世界状态无重大变化，可共享部分计划模板。
2. **降级机制**：当LLM服务不可用或超时时，自动切换至预设的**规则脚本计划库**（如“战备脚本”、“休养脚本”）。
3. **批量规划**：对于T2级（金丹期）NPC，可使用更轻量的小模型（如7B参数量）或本地部署模型。
4. **时间分片**：将全区服NPC的LLM调用分散在游戏日的不同时段，避免峰值压力。

### 7.2 玩家感知优化

- **异步生成**：玩家交互时，若NPC计划正在生成中，显示“此人心事重重，似在谋划什么……”的占位文本。
- **延迟生效**：LLM计划生成后，在下一个游戏日开始时生效，给系统留出处理时间。

## 8. 与现有行为树的融合示例

以“秦国白起”为例，展示LLM计划如何驱动行为树：

**背景**：白起为秦国一级家族“白氏”的家主，化神初期，T1级NPC。

**LLM生成的周计划**：
```json
{
  "primary_goal": "削弱楚国前线补给，为秦王东出争取优势。",
  "sub_tasks": [
    {"task_id": 1, "description": "率亲卫队深入楚境，摧毁丹阳粮仓。", "action_type": "COMBAT_RAID"},
    {"task_id": 2, "description": "战后返回家族，指导族中后辈剑法。", "action_type": "TEACH"}
  ]
}
```

**执行过程**：
- **游戏日1-3**：白起的行为树优先级2被注入`COMBAT_RAID`任务，表现为“移动至楚境→攻击楚军粮仓守军→摧毁建筑→撤离”。期间若遭遇玩家攻击，优先级1的生存应急子树会临时接管。
- **游戏日4-7**：返回家族后，行为树执行`TEACH`任务，表现为“在演武场停留→与前来请教的NPC/玩家交互→提升对方剑法熟练度”。

**玩家交互**：玩家若在此期间向白起请教剑法，会获得比平时更高的收益（因为正执行教导计划）。

```
秦王 LLM 计划 → 生成“给白起的密诏”文本
                ↓
```

这些文本可作为**游戏内彩蛋**，玩家通过截获信使、探索密室等方式获取，增加世界沉浸感。

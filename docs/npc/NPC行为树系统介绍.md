# NPC 行为树系统介绍

> 在《太古纪元：霸业》的修仙世界中，每一个 NPC 都是**活着的个体**——他们会饿、会累、会有朋友和仇敌，会闭关修炼追求突破，也会服从家族长老的命令奔赴战场。这一切，都由一套名为**行为树**的系统驱动。

---

> **架构说明**：本文档标题沿用"行为树"的通俗叫法以便理解，但从技术实现角度，本系统采用的是**分层优先级决策架构（Hierarchical Priority Decision System）**。与传统树形行为树（以 Sequence/Selector/Decorator 节点组织、通过 tick 遍历）不同，本系统通过 7 层严格降序优先级依次求值，配合行为惯性迟滞、查表分发执行、三维行为标签微规划、叙事状态机LLM感知、决策链日志，更接近 Utility AI 与 HTN 的混合架构。详情请见[系统代码设计文档](../code-design/06-NPC行为与生命周期代码设计.md)。

---

## 一、NPC 在想什么？—— 七层优先级决策（含情绪打断）

每个 NPC 在世界的每一帧（约 60 次/秒）中都要问自己一个问题：**"我现在应该做什么？"**

答案是逐层判断的，高优先级的决策会覆盖低优先级：

```
┌────────────────────────────────────────────┐
│  🚨 第一层：生存（Survival）                  │
│  HP < 30% → 逃跑保命                        │
│  HP < 50% → 原地疗伤                         │
│  ✨ 已加入惯性保护：进入生存行为立即生效，       │
│     退出需 HP 持续稳定数帧，避免临界值抖动      │
├────────────────────────────────────────────┤
│  💢 第二层：情绪（Emotion）    ← V6 新增      │
│  愤怒 ≥ 阈值 → 不顾一切发起决斗               │
│  恐惧 ≥ 阈值 → 即使HP正常也会逃跑              │
│  喜悦 → 主动分享/赠送资源                     │
│  ⚠ 生存本能始终高于情绪（HP<15%强制保命）     │
│  🔒 V6.1：情绪冷却——同一人决斗失败后72帧不重试 │
├────────────────────────────────────────────┤
│  📜 第三层：指令（Command）                   │
│  族长下令攻城？立刻出发！                     │
│  忠心的弟子接受，贪婪的弟子可能截留战利品       │
├────────────────────────────────────────────┤
│  🤖 第四层：LLM 计划（LLM Plan）              │
│  高层 NPC 通过 AI 大模型规划战略行动           │
│  如"秦王决定联魏伐楚"                         │
│  V6 新增：前线战报注入，高层能感知前线伤亡/资源  │
├────────────────────────────────────────────┤
│  💬 第五层：社交（Social）                    │
│  想朋友了？上门拜访                           │
│  有恋人了？约会增进感情                        │
│  有弟子了？传道授业                           │
│  闲聊时可能把目击的八卦传播出去（V6 新增）      │
│  📢 V6.1：流言按事件严重度排队，天劫优先于闲话  │
│  😱 V6.2：群体恐慌传染——30%人恐惧就能感染整条街 │
├────────────────────────────────────────────┤
│  🧘 第六层：修炼（Cultivation）               │
│  勤奋的 NPC 会选择打坐修炼                    │
│  修为满了？尝试突破境界                        │
│  卡瓶颈了？外出寻访机缘                        │
├────────────────────────────────────────────┤
│  🌅 第七层：日常（Daily）                     │
│  饿了吃饭，困了睡觉                           │
│  没有特别的事就按身份和性格选择日常活动         │
│  V6 新增反思：采矿老亏钱？下次改行             │
│  🧠 V6.1：遗忘因子——隔段时间再试试原行当       │
│  💡 V6.2：微规划——全部行为都不行时"发明"新活法 │
└────────────────────────────────────────────┘
```

> **一句话理解**：一个受伤的弟子原本在修炼，但 HP 低于 30% 时，生存本能会让他立刻逃跑。伤势恢复后，如果处于极度愤怒状态，他可能不顾命令去找仇人决斗。如果族长有命令在身，他就去执行命令；如果没有，他可能去找朋友聊聊，或者在闲聊中把目击过的八卦传播出去。

### 行为惯性——告别"抽搐"

V6 引入了**行为惯性（迟滞）机制**来解决临界值附近的"行为抖动"：

- **低优先级→高优先级**：立即切换（如日常→生存，不犹豫）
- **高优先级→低优先级**：需条件持续满足 N 帧才降级（如 HP 恢复到 35% 后还要稳定 5 帧才退出逃跑）
- **外部强制事件**：LLM 指令、被攻击 → 无视惯性，立即切换

这彻底解决了 V5 中"HP=31%→29%→反复横跳"的问题。

### 情绪冷却——告别"暴怒卡死"（V6.1）

情绪层让 NPC 能冲动行事，但惯性+情绪组合产生了新问题：一个被辱骂的弟子愤怒决斗→失败→再次被辱骂→再愤怒→再决斗→再失败，**死循环**。

V6.1 引入了**情绪冷却**：对同一目标因同一原因触发的情绪行为，72 帧内不再重复触发。冷却期间愤怒继续累积，但不会再次发起决斗——多余的愤怒会**溢出转化为恐惧**（"打不过→害怕"）。

### 流言优先级——大事不会被小事淹没（V6.1）

V6 的流言传播每帧限额 50 条。但当 200 个 NPC 聚会时，50 条配额可能全被"某人挖到灵石"占满，而"长老私吞巨款"反而没传开。

V6.1 改为**按事件严重度排队**：目击天劫（严重度 10）、刺杀（9）、背叛（8）优先传播。普通八卦滞留超过 300 帧后严重度自动 +1（"陈年旧事"效应），超过 600 帧仍未传播则自然过期。

### 反思遗忘——别让运气决定人生（V6.1）

"采矿连续 3 次产出低→权重 ×0.5"的反思机制有一个隐患：某个 NPC 确实擅长采矿，只是运气不好连续 3 次失败（概率上完全可能），就永久降低了采矿倾向。

V6.1 加入了**遗忘因子**：即使没有替代行为成功，500 帧后权重自然向 1.0 恢复一半距离，模拟"隔段时间再试试"的心理。恢复速率还受性格影响：**勤奋的人更愿意再试**（×1.5），多次失败后恢复变慢（饱和效应，最低 ×0.2）。

## 二、NPC 在做什么？—— 50 种行为总览

当前系统支持 **50 种** 不同的 NPC 行为，分为 8 个类别：

### 🚨 生存类（3 种）

| 行为 | 说明 |
|:---|:---|
| 逃跑 (Flee) | 向远离威胁的方向移动，同时缓慢回血 |
| 疗伤 (Heal) | 原地打坐，恢复 HP 和 MP |
| 固守 (Defend) | 坚守当前位置，微量恢复 HP |

### 🌅 日常类（6 种）

| 行为 | 说明 |
|:---|:---|
| 进食 (Eat) | 消耗食物，恢复饥饿值 |
| 休息 (Rest) | 原地休整，恢复 HP/MP/精力 |
| 睡眠 (Sleep) | 深度睡眠，大量恢复 HP/MP/精力 |
| 散步 (Walk) | 在区域内随机漫步 |
| 闲聊 (Chat/Gossip) | 与他人交谈，满足社交需求；V6 可传播流言 |
| 待命 (AwaitOrders) | 原地待命，等待上级指令，缓慢恢复 HP |

### 🧘 修炼类（6 种）

| 行为 | 说明 |
|:---|:---|
| 修炼 (Cultivate) | 打坐修炼，积累修为进度 |
| 突破 (Breakthrough) | 冲击下一境界，成功则属性大幅提升 |
| 渡劫 (Tribulation) | 元婴→化神必经天劫，持续承受天雷伤害 |
| 冥想 (Meditate) | 深度冥想，缓慢恢复 MP 并增加修为 |
| 炼丹 (Alchemy) | 消耗材料产出丹药，谨慎的 NPC 更倾向此道 |
| 寻访机缘 (SeekFortune) | 向随机方向探索，野心的 NPC 卡瓶颈时会触发 |

### 💬 社交类（8 种）

| 行为 | 说明 |
|:---|:---|
| 访友 (VisitFriend) | 向关系最好的 NPC 移动，到达后增进感情 |
| 约会 (Date) | 与道侣相会，增进亲密度，可能生育后代 |
| 家族聚会 (FamilyGathering) | 响应家族号召，向聚会地点聚集 |
| 传授 (MentorTeach) | 师父教导弟子，弟子修为增长 |
| 请教 (DiscipleAsk) | 弟子向师父请教，若师父境界更高则获得修炼加成 |
| 交易 (Trade) | 进行物品买卖，有盈有亏 |
| 八卦 (Gossip) | 闲聊八卦，满足社交需求；V6 新增流言传播机制 |
| 复命 (ReportTask) | 完成任务后向上级报告 |

### 🔨 生产类（13 种）

| 行为 | 说明 |
|:---|:---|
| 建造 (Build) | 消耗灵石，推进建筑进度 |
| 采矿 (Mine) | 在矿脉附近产出灵石 |
| 耕种 (Farm) | 播种→生长→收获，产出灵石 |
| 捕鱼 (Fish) | 在渔场产出灵石 |
| 伐木 (Lumber) | 在林地产出灵石 |
| 采集 (Gather) | 野外采集，产出灵石 |
| 锻造 (Craft) | 消耗灵石打造装备 |
| 精炼 (Refine) | 消耗灵石精炼材料 |
| 烹饪 (Cook) | 消耗灵石制作食物 |
| 建造大型 (Construct) | 消耗灵石进行大型建造 |
| 修理 (Repair) | 消耗灵石修理装备/建筑 |
| 出售 (Sell) | 卖出物品换取灵石 |

### ⚔️ 战斗类（9 种）

| 行为 | 说明 |

| 行为 | 说明 |
|:---|:---|

| 小队协调 (CoordinateSquad) | 与小队成员协同行动 |

## 三、NPC 之间的"社交网络"

NPC 不只是孤立的个体——他们之间有着复杂的关系网络。

### 关系矩阵

每个 NPC 维护一个**人际关系列表**（最多 50 个人），每条关系包含：

- **亲密度**：从 -100（不共戴天之仇）到 +100（生死之交）
- **特殊关系**：道侣、师父、徒弟
- **末次互动时间**：V6 新增，用于判断关系是否需要自然衰减

```
亲密度 > 40  ──→  35% 概率友好交流（双方 +3 亲密度）
亲密度 > 20  ──→  25% 概率资源交换（双方获得灵石）
亲密度 < -20 ──→  25% 概率发生冲突（双方受伤）
亲密度 < -50 ──→  15% 概率决斗（大幅受伤，败方 -15 亲密度）
```

### 关系自然衰减（V6 新增 + V6.1 阵营偏见）

长期不互动的 NPC 之间，关系会自然降温——这避免了 V5 中"时间久了所有人都是朋友"的问题：

- **正亲密度衰减**：长期无互动后缓慢下降至 0（陌生人保底）
- **负亲密度消解**：仇敌关系随时间缓慢回升——但**敌对家族成员的回升有底线**，不会完全归零（V6.1 阵营偏见）
- **衰减速率**：由性格决定——**忠诚≥70 的 NPC 念旧，衰减慢**；**贪婪≥70 的 NPC 薄情，衰减快**
- **特殊保护**：道侣、师徒之间衰减率仅为普通的 50%

### 社交记忆（三层结构，V6 重构）

NPC 的记忆分为三层：

| 层级 | 容量 | 内容 | 用途 |
|:---|:---|:---|:---|
| **近期记忆** | 20 条精确记录 | 完整细节：谁、何时、何事、结果、情感标签 | 快速决策参考 |
| **中期记忆** | 100 条压缩摘要 | 按对象聚合：互动次数、平均情感分、时间范围 | LLM 上下文（TOP 10） |
| **长期记忆** | 50 条里程碑 | 重大事件：突破境界、道侣结合、生死之战、家族战争 | LLM 规划（全量注入） |

> 一个活了 300 年的元婴修士，现在真正拥有跨越世纪的记忆——而不是只记得最近 30 件事。

### 信息传播：八卦/流言（V6 新增）

NPC 在闲聊（Gossip）时，会将自己目击的重大事件传播给聊天对象：

```
NPC A 目击长老私吞灵石 → 闲聊时告诉 NPC C → C 告诉 NPC D
  完整信息              细节衰减             "据说长老贪污！"
```

- **传播条件**：亲密度 > 30 且谨慎 < 60 才会传播（谨慎的人嘴严）
- **传播优先级**：按事件严重度加权排队——目击天劫（10级）优先于日常闲聊（1级）（V6.1）
- **信息扭曲**：每传播一次，内容完整度降低 15+，三次转述后可能面目全非
- **陈年旧事**：滞留超过 300 帧的八卦严重度自动 +1；超过 600 帧无人传播则自然消散（V6.1）
- **当事人反应**：流言传到当事人耳中 → 高谨慎者私下摆平，低谨慎者公开暴怒
- **性能保护**：每帧最多 50 次传播，仅在已发生的社交互动中计算

### 阵营偏见（V6.1 新增）——敌人不会变成路人

关系衰减让仇恨随时间淡化是好的，但两个家族因战争结下世仇后，敌对弟子三百年后见面像没事人——这反而**不自然**了。

V6.1 引入了**阵营偏见**：家族/宗门间的关系作为一个"场"施加偏置力：

> 家族 A 与家族 B 立场亲和度 **-40** → 两族弟子的个人负亲密度衰减到 **-10** 后停止，不会归零

但这不意味着两人永远无法和解——如果 NPC_X 主动帮助 NPC_Y，亲密度可以**突破阵营底线**上升到正值。"患难见真情"仍然可能发生。

## 四、性格决定命运——NPC 的六个性格维度

每个 NPC 都有六个性格维度（0-100），深刻影响他们的行为：

| 性格 | 影响 |
|:---|:---|
| **忠诚 (loyalty)** | 忠诚 ≥ 70 必定执行上级命令；忠诚 < 30 可能抗命；忠诚影响关系衰减速率 |
| **野心 (ambition)** | 野心 > 80 时，30% 概率超额完成命令（产出 1.2-1.5 倍） |
| **谨慎 (caution)** | 谨慎 > 70 时，战斗中 HP < 50% 会优先保命撤退；谨慎调节愤怒触发阈值 |
| **贪婪 (greed)** | 贪婪 > 70 时，25% 概率在执行采集任务时截留 10-30% 资源；贪婪加速关系衰减 |
| **勤奋 (diligence)** | 勤奋的 NPC 更倾向修炼而非休息 |
| **社交 (sociability)** | 社交 ≥ 60 时更倾向社交行为；社交影响喜悦情绪阈值（社交高者更容易感到喜悦） |

### 瞬时情绪（V6 新增）——比性格更快的变数

性格是慢变量（几乎不变），而情绪是**快变量**（每帧都在变化）：

| 情绪 | 触发事件 | 衰减 | 突破阈值后 |
|:---|:---|:---|:---|
| **愤怒** | 被辱骂 +20、被攻击 +15 | 每帧 ×0.995 | 发起决斗（谨慎高者阈值更高，**冷却期内转为恐惧**） |
| **恐惧** | 被攻击 +30、**群体恐慌传染** | 每帧 ×0.995 | 触发逃跑（即使 HP 正常） |
| **喜悦** | 社交成功 +10、收到礼物 +25、**群体欢腾传染** | 每帧 ×0.995 | 主动赠送资源/分享八卦 |

> **举个例子**：一个忠诚 85、野心 90、谨慎 30 的弟子收到"采矿"命令时——他 100% 接受命令（高忠诚），有 30% 概率产出 1.2-1.5 倍灵石（高野心）。但如果连续被三个同门辱骂，他的愤怒会持续累积，最终在采矿途中突然停下，向辱骂者发起决斗（情绪打断指令层）。而且由于他谨慎只有 30，愤怒阈值低（60），非常容易冲动。

## 五、LLM 驱动的高层战略——"秦王"在想什么？

游戏中的高层 NPC（T0-T2 层级，如秦王、白起、家族长老）的决策并非写死的规则，而是由 **AI 大模型（LLM）实时规划**的。

### 指令链：从秦王到士兵（V6 新增自下而上反馈）

```
T0 "秦王" ───→ 决定"联魏伐楚"的策略
  │              ↑
  │              │ 收到前线摘要：伤亡率 40%，矿脉被妖兽占领
  ├──────────────┘
  ▼
T1 "白起" ───→ 将策略拆解为三路兵马的战术
  │              ↑
  │              │ 标记"东路军伤亡过半，建议撤退"
  ├──────────────┘
  ▼
T2 "长老" ───→ 将战术拆解为具体任务："你去占领东侧矿脉"
  │
  ▼
T3 "弟子" ───→ 收到命令，根据性格决定接受/拒绝/超额完成
  │
  ▼
  执行完毕 → 向上逐级汇报 → T0 根据前线摘要调整下一轮战略
```

V6 的关键改进：LLM 规划不再是建立在"理想世界"假设上的。高层的 prompt 中会注入**前线摘要**——下属 NPC 的伤亡率、资源消耗、任务完成率、异常事件——让"秦王"知道前线矿脉被妖兽占领了，下次规划时就不会再命令弟子去送死。

## 六、NPC 如何"学习"？——行为反思（V6 新增）

V6 引入了一个轻量级的**反思循环**——NPC 会根据历史结果调整未来的行为倾向，无需 LLM 参与，只有计数器和阈值：

```
采矿连续 3 次产出低于预期 → 采矿权重 ×0.5，"我可能不适合采矿"→ 改试耕种
与某人连续 2 次社交结果为负面 → 回避该对象，"这人总让我不爽"
探索某区域连续 3 次无收获 → 降低该区域优先级，"那边没东西"
━━━━━━━━━━━━━━━━━━━━━
替代行为成功后 → 原行为的权重恢复至 1.0
即使无替代成功 → 500 帧后自然恢复（V6.1 遗忘因子）
全部行为都碰壁 → 触发微规划，"换个完全不同的活法"（V6.2）
```

这让 NPC 的行为具有了"试错"和"适应"的特征——他们会避开失败的策略，尝试新的方向。

### 群体情绪场——恐慌会传染（V6.2）

V6 的情绪是个体的。但修仙世界最精彩的场景——**集体恐慌、宗門热血、万众一心**——都需要群体效应。

V6.2 引入了一个轻量级方案，直接利用已有的流言传播管道：当 NPC 闲聊（Gossip）时，除了传播流言，还会检测周围 NPC 的情绪状态。如果**半径范围内超过 30% 的 NPC 处于同一种高情绪状态**，闲聊会自动将该情绪传染给聊天对象：

> 妖兽攻城 → 目击者恐惧飙升 → 闲聊时情绪感染路人 → 整个城镇恐慌
> 
> ——不需要每个人都知道发生了什么，只需要看到别人在害怕。

恐惧传染量 = 15 × 恐惧比例，愤怒 = 10 × 愤怒比例，喜悦 = 10 × 喜悦比例。范围半径 200 单位，至少 3 人才会产生场效应。

### 微规划——"发明"新活法（V6.2）

反思和遗忘能让 NPC 在已有 50 种行为中切换，但如果一个 NPC **所有已知行为都不行**呢？

V6.2 的**微规划**是轻量级的"自我改写"：当反思系统追踪到 NPC 全部已知行为的权重都 < 0.7，且连续卡住 5 帧以上，系统触发一次**创意行为映射**：

```
采矿→采集  捕鱼→狩猎  伐木→采集  锻造→贸易
修炼→寻机缘  探索→寻宝  巡逻→侦查  休息→散步
```

这不是真的创新——而是从行为表中找一个"最接近的但不同的"行为来试。性格也影响选择：高野心的 NPC 选探索，高谨慎的选冥想。

同时，TS 层预留了 `requestMicroPlan()` 接口——未来接入 LLM 后，真正的主角 NPC 可以获得**独一无二的行为**，突破 50 种限制。

## 七、技术架构——怎样让上千个 NPC 不卡？

从技术角度看，行为树系统经历了 **8 轮迭代**，当前采用了一套精巧的架构：

### 决策与执行分离

```
每一帧的处理流程：
┌──────────────────────────────────────┐
│  第一阶段：决策（evaluate）            │
│  ├─ 50% NPC 被跳过（分频评估）         │
│  ├─ 有行为树模板的 NPC → 模板化评估    │
│  ├─ 其余 NPC → 7 层优先级逐个判断      │
│  │   Survival → Emotion → Command    │
│  │   → LLM → Social → Cultivation    │
│  │   → Daily（含反思+遗忘+微规划）      │
│  └─ 行为惯性检查（防抖）               │
├──────────────────────────────────────┤
│  第二阶段：执行（execute）             │
│  ├─ 情绪衰减（每帧 ×0.995）            │
│  ├─ 行为结果记录（反思数据）           │
│  └─ 查表分发 → 按类别批量执行          │
└──────────────────────────────────────┘
```

### 性能优化手段

- **分频评估**：修炼中的 NPC 每 30 帧才重新决策一次，战斗中的 NPC 每帧决策
- **模板化**：5 种角色预设模板（家主/护卫/弟子/工人/战斗），代码在编译期就确定了决策路径
- **黑板缓存**：用 1 字节的位域缓存"饿不饿/累不累/有没有危险"等条件判断结果
- **WASM 编译**：C++ 代码编译为 WASM，所有 NPC 数据采用 SoA（数组结构）紧凑排列，10K NPC 仅需 ~40MB 内存
- **空间索引**：NPC 间的交互检测从 O(n²) 优化为 O(n × 邻居数)
- **信息传播限制**：每帧最多 50 次流言传播，仅在已有社交互动中触发；按事件严重度排队，高冲击事件优先
- **情绪冷却 O(1)**：环形缓冲查找，最多 8 条记录
- **反思恢复 O(1)**：仅根据当前帧号和惩罚历史计算，无额外遍历

### 代码组织

```
BehaviorTreeSystem.h     ← 决策层：7 层优先级 + 惯性 + 情绪冷却 + 微规划 + 反思遗忘 + 查表分发
├── ExecuteDescriptor.h  ← 基础设施：执行描述表 + 惰性获取上下文
├── BehaviorTree_Survival.h       ← 3 种生存行为
├── BehaviorTree_Daily.h          ← 6 种日常行为
├── BehaviorTree_Cultivation.h    ← 6 种修炼行为
├── BehaviorTree_Social.h         ← 8 种社交行为（含流言传播、情绪传染、情绪触发）
├── BehaviorTree_Production.h     ← 13 种生产行为（含反思记录）
├── BehaviorTree_Combat.h         ← 9 种战斗行为（含情绪触发）
├── BehaviorTree_Exploration.h    ← 3 种探索行为（含反思记录）
└── BehaviorTree_Command.h        ← 2 种指令响应行为

组件层（ECS Components）：
├── BehaviorComponent.h  ← 行为状态 + 惯性字段 + 反思数据（含遗忘因子、微规划触发）
├── SocialComponent.h    ← 社交需求 + 瞬时情绪（anger/fear/joy）+ 情绪冷却记录
├── RelationshipComponent.h ← 关系 + 衰减速率 + 上次互动帧 + 阵营偏见表
├── MemoryRingComponent.h  ← 三层记忆（近期/中期/长期）+ 流言数据（含严重度）
└── PersonalityComponent.h ← 性格（影响情绪阈值、衰减速率、遗忘恢复速率）

TypeScript 服务层：
├── NPCWorldService.ts    ← 关系衰减调度 + 阵营偏见 + 前线数据采集 + 微规划钩子
└── LLMPlanningService.ts ← 前线摘要注入 + 修正建议传递
```

## 八、如何添加一个新行为？

假设你想让 NPC 可以"在茶馆喝茶"：

1. 在枚举中添加 `TeaDrinking`
2. 在合适的分类头文件（如 `BehaviorTree_Daily.h`）中写一个函数：
   ```cpp
   static void exec_teaDrinking(ExecuteContext& ctx) {
       auto* social = ctx.getSocial();
       auto* resources = ctx.getResources();
       if (social) social->onSocialize();
       if (resources) resources->spiritStones -= 10;
       // V6: 记录反思数据
       auto* behavior = ctx.getBehavior();
       if (behavior) behavior->reflection.recordResult(NPCActivity::TeaDrinking, 3);
   }
   ```
3. 在 `kExecuteTable[]` 中加一行：
   ```cpp
   {NPCActivity::TeaDrinking, "TeaDrinking", ActivityCategory::Daily, REQ_SOCIAL|REQ_RESOURCES, exec_teaDrinking},
   ```

**不需要改动任何 switch-case 或决策逻辑，三步完成。**

## 九、V5 → V6 → V6.1 → V6.2 → V6.3 → V7 → V7.1 → V7.2 迭代总览

| 版本 | 新增能力 | 解决问题 |
|:---|:---|:---|
| **V6** | **行为惯性** | NPC 在 HP≈30% 临界值附近反复横跳（"抽搐"） |
| | **瞬时情绪** | NPC 只有慢变量性格，缺少"一时冲动"的快变量 |
| | **关系衰减** | 时间久了所有人都是朋友，失去戏剧张力 |
| | **三层记忆** | 20 条记忆不符合修仙世界 300 年寿命的设定 |
| | **前线摘要** | LLM 高层战略无法感知前线伤亡和资源消耗 |
| | **行为反思** | NPC 不会从失败中学习 |
| | **流言传播** | 目击事件只能存在个人记忆中，无法在社交网络中扩散 |
| **V6.1** | **情绪冷却** | 愤怒决斗→失败→再愤怒→再决斗的死循环（"暴怒卡死"） |
| | **流言优先级** | 大量低重要性闲聊挤占传播配额，高冲击事件传不开 |
| | **反思遗忘** | 概率性失败导致 NPC 永久偏离最优行为（"过拟合"） |
| | **阵营偏见** | 敌对家族成员随时间变成陌路，失去阵营张力 |
| **V6.2** | **群体情绪场** | 情绪是个体的，缺少集体恐慌/宗門热血等群体涌现 |
| | **微规划** | NPC 所有行为都碰壁时无法突破，缺少"主角感" |
| **V7** | **LLM 生存感知** | LLM 规划期间 NPC 对生存威胁无响应（被攻击也不逃跑） |
| | **交互记忆时间戳补全** | InteractionSlot.timestamp 从未赋值，记忆凝固时间门控失效 |
| | **情绪冷却 LRU 淘汰** | 冷却槽满 16 后拒绝写入，高密度场景暴怒卡死回潮 |
| | **C++/TS 管线收敛** | 关系衰减双写参数不一致，TS 端收敛为纯 LLM 编排层 |
| | **评估层接口化** | evaluate() 40 行 if-return 链改为 kEvaluateLayers[] 函数指针数组 |
| | **空间索引接入** | 流言听众选择和情绪传染统计从全实体扫描改为 SpatialIndexCache 邻居查询 |
| **V6.3** | **情绪衰减时间驱动** | 情绪衰减与帧率耦合，不同帧率下衰减速度不一致 |
| | **情绪冷却溢出保护** | 冷却记录满时 FIFO 覆盖导致目标冷却意外消失 |
| | **群体情绪场最小人数** | 小样本（3人中1人恐惧）误触发群体恐慌 |
| | **行为执行前环境检查** | 选择不可执行行为后失败→反思惩罚→负循环 |
| | **流言 TTL 与容量保护** | 流言无限堆积，旧流言永远不会自然消失 |
| | **记忆凝固规则** | 三层记忆缺乏升级触发条件，记忆池只是独立数据池 |
| | **行为元标签体系** | 微规划映射手工硬编码，50+行为时难以维护 |
| | **文档架构正名** | "行为树"命名与实现不匹配 |
| **V7.1** | **叙事状态机** | LLM 高层收到的前线数据是冰冷的统计数字，缺乏叙事直觉，生成的战略指令"没有人味" |
| | **行为标签多维化** | V6.3 的元标签只有单维位掩码，微规划无法区分职业/资源/性格；新增 CareerTag + ResourceTag + PersonalityTag 三维标签体系 |
| | **社会角色粘性** | 反思+微规划导致所有失败的 NPC 最终趋同于最高效行为，失去社会分工多样性 |
| | **意义构建日志** | 设计师无法追溯 NPC 决策的因果链，涌现行为难以调试和验证 |
| | **标签相似度匹配** | 微规划从硬编码映射表全面切换为标签相似度驱动，新增行为自动纳入匹配范围 |
| **V7.2** | **角色基线权重** | 反思可能导致所有NPC长期行为趋同，矿工最终都去钓鱼 |
| | **玩家可读性暴露** | NPC行为由十几种变量交叉决定，玩家无法理解NPC为什么这样做 |
| | **LLM意图式规划** | LLM调用延时+具体命令过时，等"联魏伐楚"命令下达时楚国可能已灭 |
| | **社交求助行为** | NPC走投无路时只会在内部映射新行为，缺少社会求助出口 |
| **V7.3** | **经济数值修复** | collectTax 双重征税导致实际税率 0.25%（设计 5%）；exec_buy 不扣灵石导致 NPC 无限刷装备 |
| | **需求衰减调度修复** | tickDecay 在 evaluateDaily 中被每 NPC 每帧调用，需求衰减速度是设计的 10000 倍 |
| | **灵石溢出修复** | exec_sell 的 amount×price 乘法和 exec_bargain 纯收益行为导致灵石凭空产生 |
| | **智能税率** | SetTaxRate 从灵石余额模运算改为基于 EconomicDigest 态势+性格的智能决策 |
| | **经济危机阻断** | evaluateEconomicCrisis 中 T1/T2 执行动员后返回 true 阻断后续决策层 |
| | **反向索引优化** | 经济危机时同族成员查找从全实体遍历 O(N) 降为 clanId 反向索引 O(clanMembers) |
| | **阵营亲和度修复** | setFactionAffinity 从步进 +1/-1 改为一步到位直接赋值 |
| | **情绪衰减保护** | tickEmotions 对 deltaTime 尖峰添加上限保护，防止 GC 暂停导致情绪骤降 |

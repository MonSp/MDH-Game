## 5. 渲染架构

### 5.1 Three.js 场景结构

```
<Canvas shadows>
  ├── <fog>                           # 迷雾效果
  ├── <OrthographicCamera>            # 正交相机（45度等距视角）
  ├── <ambientLight>                  # 环境光
  ├── <directionalLight>              # 主平行光（模拟太阳）
  ├── <Terrain>                       # 地形层（Simplex噪声生成）
  ├── Capitals                        # 都城标记
  ├── ResourcePoints                  # 资源点（灵田/矿脉/遗迹）
  ├── NPCs                            # NPC实体
  └── Player                          # 玩家实体
</Canvas>
```

### 5.2 正交相机配置

```typescript
position={[20, 20, 20]}    // 45度等距视角
zoom={40}                  // 缩放级别
near={-100}
far={100}
```

### 5.3 渲染优化策略

- **视野裁剪**: 仅渲染玩家视野半径（15格）内的实体
- **Memoization**: 使用 `useMemo` 缓存角色外观和地形计算
- **地形预计算**: 使用 Simplex 噪声按需生成地形，避免预加载整个地图
- **动画帧优化**: 使用 `useFrame` 实现平滑的角色呼吸/移动动画

### 5.4 地形生成算法

```typescript
// 低频噪声（宏观大洲） + 高频噪声（微观起伏）
macroNoise = noise2D(x * 0.02, y * 0.02)    // 宏观地形
microNoise = noise2D(x * 0.08, y * 0.08) * 0.3  // 微观细节
value = macroNoise + microNoise

// 生物群落映射
DEEP_WATER  -> 湛蓝 (-0.4以下)
SHALLOW_WATER -> 浅蓝 (-0.1以下)
SAND        -> 黄色 (0.05以下)
GRASS       -> 绿色 (0.4以下)
FOREST      -> 深绿 (0.7以下)
ROCK        -> 灰色 (0.9以下)
SNOW        -> 白色 (0.9以上)

// 道路系统
固定坐标模8生成道路网络
```

### 5.5 角色外观系统

三层叠加模型：
1. **光环层**: 由境界决定颜色、大小、透明度
2. **躯体层**: 由职位/家族决定服饰颜色
3. **特效层**: 由体质决定发光效果

```
境界光环: 白(凡人) → 蓝(练气) → 紫(筑基) → 金(金丹) → ...
体质特效: 剑体(金色) | 雷灵体(紫色) | 药王体(绿色) | 战体(红色)
```

## 7. 数据流设计

### 7.1 玩家操作流

```
用户输入（键盘/鼠标）
  ↓
React事件处理
  ↓
调用 gameStore action
  ↓
更新 Zustand 状态
  ↓
React 组件自动重新渲染
  ↓
Three.js 场景更新
```

### 7.2 NPC自治演化流

```
Game.tsx useEffect
  ↓
setInterval(1000ms)
  ↓
调用 updateNPCs()
  ↓
遍历所有 nearbyNPCs
  ↓
evaluateNPCBehavior(npc)
  ↓
评估行为树（4层优先级）
  ↓
更新 NPC 状态和位置
  ↓
检查执法长老碰撞
  ↓
触发战斗（如有碰撞）
  ↓
状态更新 → UI 刷新
```

### 7.3 市场价格波动流

```
玩家交易 / 定时触发
  ↓
updateMarketPrices()
  ↓
遍历所有商品
  ↓
计算价格波动 (-5% ~ +5%)
  ↓
应用库存修正
  ↓
限制价格区间 (50% ~ 200%)
  ↓
更新 market 状态
```

## 8. 核心算法实现

### 8.1 NPC行为树评估

```typescript
function evaluateNPCBehavior(npc, state):
  // 执法长老特殊逻辑
  if npc.role == '执法堂长老' and npc.targetPlayerId:
    向玩家移动追踪
  
  // 优先级1：生存应急
  if npc.hp < npc.maxHp * 0.3:
    返回"重伤逃遁"状态
  
  // 优先级2：家族职责
  if npc.role in ['家主', '长老']:
    评估跑商/闭关/巡逻
  
  // 优先级3 & 4：权重轮盘赌
  weights = { patrol:10, retreat:10, logistics:10, explore:10, work:10, rest:10 }
  weights += 职位修正 + 国家修正 + 人格修正 + 环境修正
  
  选择权重最高的行为
  执行对应动作
```

### 8.2 战斗判定

```typescript
function resolveCombat(player, npc):
  playerAttack = player.stats.attack * 国家加成
  winChance = playerAttack / (playerAttack + npc.power / 10)
  winChance = clamp(winChance, 0.1, 0.9)
  
  if random() < winChance:
    玩家胜利 → 获得修为+灵石
    可能掉落洗髓丹 (20%概率)
    扣除家族好感度
  else:
    玩家失败 → 损失血量
```

### 8.3 境界突破

```typescript
function breakthrough(player):
  if player.stats.exp >= player.stats.maxExp:
    cost = REALM_BREAKTHROUGH_COST[player.realm]
    if player.inventory['灵石'] >= cost:
      消耗灵石
      进入下一境界
      全属性翻倍
      修为清零
    else:
      突破失败，保留修为
```

## 9. 性能优化策略

### 9.1 渲染优化

- 视野裁剪：仅渲染15格内的实体
- useMemo 缓存计算结果
- 地形按需生成（非预加载）

### 9.2 状态优化

- 日志限制最多50条（slice(-50)）
- NPC仅维护视野范围内的数据
- 市场价格更新节流

### 9.3 算法优化

- Simplex 噪声使用固定种子，避免重复计算
- NPC行为树使用轮盘赌选择，O(n)复杂度

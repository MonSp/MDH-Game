# 修仙世界经济系统——微观·中观·宏观三层架构

> 在《太古纪元：霸业》的修仙世界中，每一枚灵石都有来处和去处。矿工从矿脉中挖出矿石，流经铁匠的熔炉变成装备，再由商贾运往他乡坊市。物价随 NPC 的劳作与交易而自然波动——没有"系统刷钱"，只有千百个经济主体在供需法则下博弈、学习、适应。本文档按**微观经济→中观经济→宏观经济**三层结构组织，使 LLM 能直接运用经济学推理能力进行战略决策。

## 一、经济哲学——修仙世界的经济学原理

### 1.1 核心设计思想

本系统的三条铁律：

| 铁律 | 含义 | 经济学对应 |
|:---|:---|:---|
| **零发行货币** | 所有灵石来自 NPC 生产行为，系统不"刷钱" | 商品货币（Commodity Money），类似金本位 |
| **供需驱动定价** | 物价由供需比实时计算，NPC 行为自动调节 | 市场均衡理论（Market Equilibrium） |
| **NPC 即市场** | 每个 NPC 既是生产者也是消费者，共同塑造市场 | 微观经济主体（Microeconomic Agents） |

### 1.2 与传统游戏经济的根本区别

| 维度 | 传统游戏经济 | 本系统 | 经济学类比 |
|:---|:---|:---|:---|
| **货币发行** | 系统无限刷钱 | 零发行——所有灵石来自 NPC 生产行为 | 商品货币 vs 法定货币 |
| **物价** | 策划手工配置 | 供需比实时计算，NPC 行为自动调节 | 市场定价 vs 计划定价 |
| **NPC 角色** | 静态商店，价格固定 | NPC 是生产者+消费者+交易者 | 经济主体 vs 静态接口 |
| **跨区交易** | 不存在或固定脚本 | 商队自动发现价差并套利 | 一价定律（Law of One Price） |
| **家族经济** | 纯剧情概念 | 家族库房自动抽税，资助弟子，有借有还 | 公共财政（Public Finance） |
| **NPC 物品** | 货币抽象化，NPC 不持有实物 | 每个 NPC 拥有独立背包（ItemSlot 堆叠） | 产权制度（Property Rights） |
| **高层决策** | 经济与战略无关 | T0-T2 NPC 通过 EconomicDigest 感知经济态势 | 经济情报驱动战略 |
| **数据权威** | TS 与 C++ 各维护一套 | C++ 为唯一数据源，TS 通过 WASM 按需拉取 | — |

### 1.3 经济学理论映射总览

本系统的每个模块都对应着经典经济学理论。理解这些映射，LLM 就能将训练中学到的经济学知识直接迁移到游戏世界的决策中：

```
┌─────────────────────────────────────────────────────────────────┐
│                  宏观经济层 (Macroeconomics)                       │
│  对应 T0 秦王的决策视角                                            │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │  货币体系(灵石) │ 财政政策(税率+库房) │ 贸易政策(商队+禁令)│    │
│  │  经济周期(四态) │ 战略经济(战争+情报)                      │    │
│  └─────────────────────────────────────────────────────────┘    │

│  代码：EconomicDigest, SetTaxRate, CaravanSystem, TradeEmbargo   │
├─────────────────────────────────────────────────────────────────┤
│                  中观经济层 (Mesoeconomics)                       │
│  对应 T1 白起、T2 长老的决策视角                                   │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │  区域市场(CommodityPool) │ 产业结构(角色模板+传承)        │    │
│  │  家族财政(Treasury) │ 价值链(六类商品产业链) │ 阵营竞争   │    │
│  └─────────────────────────────────────────────────────────┘    │
│  经济学对应：局部均衡 / 比较优势 / 公共财政 / 产业组织理论          │
│  代码：CommodityPool, PriceEngine, MarketRegistry, Treasury      │
├─────────────────────────────────────────────────────────────────┤
│                  微观经济层 (Microeconomics)                      │
│  对应 T3 弟子、工人的决策视角                                      │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │  生产理论(生产函数) │ 消费理论(效用函数) │ 劳动供给(职业选择)│    │
│  │  行为经济学(反思+遗忘+情绪传染) │ 博弈行为(截留+谈判)     │    │
│  └─────────────────────────────────────────────────────────┘    │
│  经济学对应：生产函数 / 效用理论 / 离散选择 / 行为经济学 / 博弈论   │
│  代码：ResourcesComponent, BehaviorComponent, ReflectionData     │
└─────────────────────────────────────────────────────────────────┘
```

> **一句话理解**：矿工挖出矿石 → 矿石池供给增加 → 矿石降价 → 铁匠买矿石更便宜 → 铁匠锻造更多装备 → 装备池供给增加 → 装备降价 → 商贾低价买入装备 → 运往高价区卖出 → 利润进家族库房 → 库房资助弟子突破 → 突破消耗灵石 → 灵石需求增加 → 商贾更积极买卖…… → 经济态势恶化到「危机」级别 → 长老自动下达经济动员令 → 全族 1.5 倍采矿 → LLM 向秦王汇报「国库仅剩 900 灵石，矿石价格飙升至 2.7 倍」→ 秦王决定夺取楚国矿脉或与魏国贸易联盟

## 二、微观经济——NPC 作为经济主体

> **核心概念**：每个 NPC 是一个**有限理性的经济主体**，拥有生产函数（如何产出商品）、效用函数（七层优先级决策）、劳动供给决策（选择什么职业），并受行为经济学规律（反思、遗忘、情绪传染）驱动。

### 2.1 生产理论——NPC 的生产函数

**经济学映射**：每个 NPC 执行一次生产行为，本质上是在应用一个**生产函数** `Y = f(L, K, T)`——投入劳动力、资本和技术，产出商品。

| 经济学概念 | 游戏实现 | 代码位置 |
|:---|:---|:---|
| **劳动力投入 L** | NPC 执行行为消耗的精力/时间 | `BehaviorComponent` 精力消耗 |
| **资本投入 K** | 消耗的原材料（如锻造需 5 矿石） | `ResourcesComponent::removeItem` |
| **技术水平 T** | 性格维度修正（勤奋/野心提升产出概率） | `PersonalityComponent` |
| **产出 Y** | 行为产出量 × 当前商品市价 | `exec_craft` 中 70% 概率产出 |
| **生产成本 C** | 材料成本 + 机会成本（时间） | `hasItem` 检查 + 反思记录 |

#### 2.1.1 16 种生产行为的经济映射

每个 NPC 执行生产/交易行为时，通过 `MarketRegistry::recordProduction()` / `recordConsumption()` 将产出/消耗同时写入**族级 CommodityPool**（宏观供需）和 **NPC 个人背包**（微观所有权）：

| 行为 | 消耗材料 | 消耗量 | 产出物品 | 产出量 | 个人背包变化 | 经济学角色 |
|:---|:---|:---|:---|:---|:---|:---|
| **Mine** 采矿 | — | — | Ore | 15/次 | +15 矿石 | 初级生产者（原材料） |
| **Farm** 耕种 | — | — | Food | 30-60/次 | +30~60 食物 | 初级生产者（粮食） |
| **Fish** 捕鱼 | — | — | Food | 10/次 | +10 食物 | 初级生产者（蛋白质） |
| **Lumber** 伐木 | — | — | Materials | 8/次 | +8 材料 | 初级生产者（建材） |
| **Gather** 采集 | — | — | Materials | 5/次 | +5 材料 | 初级生产者（野生资源） |
| **Craft** 锻造 | Ore | 5 | Equipment | 1（70%概率） | −5 矿石, +0~1 装备 | 二次加工者（矿石→装备） |
| **Refine** 精炼 | Ore | 8 | Materials | 2（50%概率） | −8 矿石, +0~2 材料 | 二次加工者（矿石→材料） |

| **Trade** 交易 | Equipment | 1 | SpiritStones | 10-50/次 | 卖方 −1 装备 | 市场交易（物物交换） |

#### 2.1.2 双写机制：微观产权 × 宏观统计

每到一次生产行为完成，系统执行**两条写入路径**——这对应经济学中的**微观数据（个体产权）**和**宏观数据（国民经济统计）**：

```
Mine 完成 → addItem(ORE, 15)          ← 微观：NPC 背包矿石 +15（产权变更）
          → recordProduction(Ore, 15)  ← 宏观：CommodityPool Ore supply +15（GDP 统计）
          → spiritStones += 15 × OrePrice ← NPC 灵石收益（劳动报酬）

Craft 完成 → hasItem(ORE, 5) ✓        ← 资本检查：是否有 5 矿石
           → removeItem(ORE, 5)        ← 微观：NPC 背包矿石 −5（资本消耗）
           → recordConsumption(Ore, 5) ← 宏观：CommodityPool Ore demand +5
           → addItem(EQUIPMENT, 1)     ← 微观：NPC 背包装备 +1（产出）
           → recordProduction(Equipment, 1) ← 宏观：Equipment supply +1
```

**材料不足时行为自动拒绝**：在扣除材料前，`hasItem(itemId, requiredCount)` 检查 NPC 背包。若不足，行为切换到 Rest 并记录反思负分——这对应**预算约束（Budget Constraint）**。

#### 2.1.3 边际报酬递减——反思系统的经济学本质

当前系统中，反思机制天然实现了**边际报酬递减规律**：

```
采矿第1次：产出 15 矿石，收益 = 15 × OrePrice(5.0) = 75灵石  → recordResult(+3)
采矿第2次：产出 15 矿石，收益 = 15 × OrePrice(4.8) = 72灵石  → recordResult(+2)  ← 供给增加，价格微降
采矿第3次：产出 15 矿石，收益 = 15 × OrePrice(4.5) = 67灵石  → recordResult(+1)  ← 价格继续降
连续3次中性/低分 → 反思权重降至 0.7 → NPC 转向其他行为
```

这完美模拟了**边际收益递减**：当所有人都去采矿，矿石供给增加→价格下降→采矿利润下降→矿工转向其他行业。这是亚当·斯密"看不见的手"的自发涌现。

#### 2.1.4 价值链——六类商品的产业链条

六类商品形成了清晰的**附加值递增链条**：

```
原材料层(低附加值)    加工层(中附加值)      终端层(高附加值)
  矿石(5灵石) ──→ 锻造 ──→ 装备(40灵石)    附加值 +35
  材料(4灵石) ──↗        ↘
  食物(3灵石) ──→ 烹饪 ──→ 食物+(3~4灵石)   附加值 +0~1
  灵草(50灵石)──→ 炼丹 ──→ 丹药(80灵石)    附加值 +30
```

NPC 的反思系统会自动引导他们向**高附加值环节**流动——但原材料供给减少又会推高原材料价格，使上游产业重新变得有利可图。这形成了一个**自发的产业链均衡**。

### 2.2 消费理论——七层优先级作为效用函数

**经济学映射**：NPC 的七层优先级决策本质上是一个**分层效用函数**——不是在所有选项中做连续优化，而是逐层满足需求，对应马斯洛需求层次理论。

| 需求层次 | 经济学对应 | NPC 行为 | 预算约束 | 价格弹性 |
|:---|:---|:---|:---|:---|
| **生存需求** | 必需品（Inelastic Good） | 逃跑/疗伤/固守 | HP<30% 时无条件触发，不考虑成本 | 完全无弹性 ε=0 |
| **情绪需求** | 非理性消费（Behavioral） | 决斗/逃跑/赠送 | 情绪突破阈值时无视预算约束 | 不可预测 |
| **指令需求** | 计划经济指令 | 执行命令/拒绝命令 | 忠诚≥70 时必执行 | 由忠诚度决定 |
| **社交需求** | 社会资本投资 | 访友/约会/传授 | 消耗时间，增进关系（未来收益） | 低弹性 |
| **修炼需求** | 人力资本投资 | 修炼/突破/渡劫 | 消耗灵石+时间，提升未来生产力 | 中等弹性 |
| **日常需求** | 消费品消费 | 进食/休息/购买 | 消耗灵石和物品 | 高弹性 ε>1 |

**LLM 洞察**：当 LLM 规划"秦王联魏伐楚"时，它需要理解——战争会同时冲击所有层次：生存层（伤亡→疗伤消耗丹药）、消费层（灵石→军费）、投资层（弟子突破被延迟）。一个好的战略应该**在经济可承受范围内发动战争**。

### 2.3 劳动供给——职业选择的离散选择模型

**经济学映射**：`chooseByRole` 函数本质上是一个**离散选择模型（Discrete Choice Model）**，与经济学中的 Logit 模型高度相似：

```
P(选择行为i) = baseProb_i × RoleBaselineWeight_i × economicBiasFor_i × reflectionWeight_i
```

| 经济学变量 | 代码实现 | 含义 |
|:---|:---|:---|
| 基础效用 | `baseProb`（如采矿 0.25） | 角色的默认职业倾向 |
| 个体特征效用 | `RoleBaselineWeight` | 身份标签（家主/弟子/工人）的权重修正 |
| 市场价格信号 | `economicBiasFor` = d/s 比值 | 矿石紧缺时采矿效用 ×3 |
| 历史经验效用 | `applyReflection` | 连续失败后该职业效用降低 |
| 随机扰动 | `random01()` | 模拟个体异质性和不可预测因素 |

**经济信号偏置的精确实现**：

`economicBiasFor` 函数检查 NPC 的家族传承（`factionCareerHeritage`）与行为的职业标签（`careerTags`）是否匹配，匹配后根据行为的产出资源标签（`resourceTags`）乘以对应的供需信号值：

```
矿石紧缺时 ironOreDemand = 3.0
  → Mine 行为的 economicBiasFor = 3.0
  → 矿工系 NPC 采矿概率 ×3
  → 更多 NPC 选择采矿
  → Ore supply 增加
  → 矿石价格回落
  → 信号减弱，达到新均衡
```

这是一条完整的**负反馈闭环**——不需要策划手动调参，市场自动调节。

**性格影响劳动供给弹性**：

NPC 不是完全理性的——性格影响劳动供给决策，模拟现实中不同人对工资变化的劳动供给响应差异：

| 性格 | 劳动供给效应 | 经济学对应 |
|:---|:---|:---|
| 勤奋 ≥ 70 | 修炼概率 ×1.0（愿意投入劳动） | 高劳动供给弹性 |
| 勤奋 < 30 | 采矿概率 ×0.5（偷懒） | 低劳动供给弹性 |
| 贪婪 > 70 | 25% 概率截留资源 | 寻租行为（Rent-Seeking） |
| 谨慎 > 70 | HP<50% 就撤退 | 风险厌恶型劳动者 |
| 野心 > 80 | 30% 概率超额完成（产出 1.2-1.5 倍） | 高能力个体的超常发挥 |

**收益不再固定——市场价格驱动的劳动报酬**：

V1 中 NPC 收益是硬编码的固定值（如采矿 +15 灵石/小时），现在改为：

```
NPC 收益 = 产出量 × 当前商品市价
```

同一个矿工，在矿石紧缺时（OrePrice=7.4）收益为 111 灵石/次，在矿石过剩时（OrePrice=2.6）收益只有 39 灵石/次。NPC 的反思系统会根据收益自动调整行为倾向——低收益时反思惩罚，高收益时偏好加强。

### 2.4 行为经济学——有限理性、损失厌恶与羊群效应

这是系统中最接近前沿经济学理论的部分。NPC 不是完全理性的"经济人"（Homo Economicus），而是**有限理性的行为人**（Homo Behavioralis）。

#### 2.4.1 有限理性——逐层满意而非全局最优

NPC 不做全局最优决策，而是**逐层满意（Satisficing）**——找到第一个满足条件的层级就执行，不继续搜索。这是 Herbert Simon 的有限理性理论的直接实现：面对复杂环境，理性计算的成本太高，"足够好"的决策比"最优"决策更现实。

#### 2.4.2 损失厌恶——反思系统的不对称性

反思系统中，负面结果的惩罚权重高于正面结果的奖励：

| 结果 | 权重变化 | 恢复速度 |
|:---|:---|:---|
| 连续 3 次大失败（sum ≤ -9） | 权重降至 `baselineWeight × 0.5`（-50%） | 500 帧后才开始恢复，多次惩罚后饱和（最低 ×0.2） |
| 连续 3 次大成功（sum ≥ 9） | 权重升至 `1.5`（+50%） | 无衰减保护，持续生效 |

看似对称，但**恢复机制不对称**——损失的影响远持久于收益。这完美对应了 Kahneman & Tversky 的**前景理论（Prospect Theory）**：损失带来的痛苦是同等收益带来快乐的 2-2.5 倍。

#### 2.4.3 适应性遗忘——贝叶斯学习的简化版

V6.1 引入的 500 帧遗忘因子是**贝叶斯学习**的简化版：随着新证据积累，旧信念的权重自然衰减。遗忘速率受性格调节：

| 性格 | 遗忘速率 | 经济学含义 |
|:---|:---|:---|
| 勤奋 ≥ 70 | ×1.5（更快恢复） | 更频繁地更新先验，愿意再试 |
| 勤奋 < 30 | ×0.5（更慢恢复） | 固守旧信念，不愿改变 |
| 多次惩罚后 | 最低 ×0.2（饱和效应） | 创伤记忆更持久 |

#### 2.4.4 群体情绪传染——信息级联与羊群效应

V6.2 引入的群体情绪场是经典的**信息级联（Information Cascade）**：

```
妖兽攻城 → 目击者恐惧飙升 → 闲聊时情绪感染路人 → 整个城镇恐慌
  ——不需要每个人都知道发生了什么，只需要看到别人在害怕。
```

个体观察到他人的情绪状态，将其作为"社会证据"更新自己的信念。传染公式：

| 情绪 | 传染量 | 条件 |
|:---|:---|:---|
| 恐惧 | 15 × 恐惧比例 | 半径 200 内 >30% NPC 恐惧，至少 3 人 |
| 愤怒 | 10 × 愤怒比例 | 半径 200 内 >30% NPC 愤怒，至少 3 人 |
| 喜悦 | 10 × 喜悦比例 | 半径 200 内 >30% NPC 喜悦，至少 3 人 |

### 2.5 博弈行为——截留、谈判与决斗

NPC 间的互动天然形成了博弈结构：

| 博弈场景 | 参与者 | 策略 | 均衡特征 |
|:---|:---|:---|:---|
| **资源截留** | 弟子 vs 家族 | 截留/忠诚 | 贪婪>70 时截留是占优策略（道德风险） |
| **贸易谈判** | NPC A vs NPC B | 高价/低价 | 对数定价公式隐含了纳什议价解 |
| **决斗** | 愤怒 NPC vs 目标 | 决斗/忍耐 | 情绪>阈值 时决斗（非理性博弈） |
| **流言传播** | 传播者 vs 当事人 | 传播/保密 | 谨慎<60 且亲密度>30 时传播（信号博弈） |
| **命令执行** | 上级 vs 下级 | 服从/抗命 | 忠诚≥70 时服从是占优策略 |

### 2.6 个人资产管理——ItemSlot 背包系统

每个 NPC 拥有独立的物品背包，存储在 `ResourcesComponent` 中，对应经济学中的**个人财富与产权**：

```cpp
struct ItemSlot {
    uint32_t itemId;   // 物品 ID（见 ItemRegistry）
    int32_t count;     // 堆叠数量
};

struct ResourcesComponent {
    int64_t spiritStones;         // 灵石余额（流动资产）
    std::vector<ItemSlot> items;  // 物品背包（实物资产）
    uint32_t equipmentItemId;     // 当前装备物品 ID（固定资产）
    int32_t familyContribution;   // 家族贡献值（社会资本）
};
```

**设计要点**：
- **堆叠而非散列**：同一种物品只占一个 `ItemSlot`，`vector` 在 NPC 通常持有 0-5 种物品时比 map 内存效率高得多
- **材料守卫**：Craft/Refine/Cook 等消耗型行为在扣除材料前先调用 `hasItem(itemId, count)`，材料不足时行为自动拒绝（预算约束）
- **双写机制**：生产行为同时更新 NPC 个人 items（微观所有权）和 CommodityPool（宏观供需），两者独立但一致

## 三、中观经济——家族/区域经济

> **核心概念**：每个家族/宗门是一个**独立的区域经济体**，拥有自己的市场（CommodityPool）、财政（Treasury）、产业结构（角色模板）和贸易政策。家族间的价差驱动商队套利，实现跨区域资源再分配。

### 3.1 区域市场——CommodityPool 与价格形成

#### 3.1.1 六类大宗商品

每个家族/宗门拥有一份 CommodityPool，追踪该区域六类商品的供给量（supply）和需求量（demand）：

| 商品 | basePrice | 来源行为 | 消耗行为 | 市场角色 |
|:---|:---|:---|:---|:---|
| **矿石 Ore** | 5 灵石 | Mine（采矿） | Craft、Refine、Construct | 工业原材料 |
| **食物 Food** | 3 灵石 | Farm、Fish、Cook、Hunt | Eat、Cook（加工） | 生活必需品 |
| **装备 Equipment** | 40 灵石 | Craft、Tailor、Construct、Build | —（耐久消耗未来扩展） | 资本品 |
| **材料 Materials** | 4 灵石 | Lumber、Gather、Refine | Craft、Build、Construct、Repair | 建筑材料 |
| **丹药 Pills** | 80 灵石 | Alchemy | Breakthrough、Heal | 高端消费品/投资品 |
| **灵石 SpiritStones** | 1 灵石 | Sell、Bargain、Trade | Buy、Breakthrough | 货币（交换媒介+价值储藏） |

> **灵石的双重身份**：灵石既是流通货币也是商品。它的供需同样受市场调节——开采矿石转化为灵石（通过出售），突破/战争消耗灵石。供过于求时灵石购买力下降（通胀），供不应求时灵石更值钱（通缩）。这类似于金本位制度下黄金的角色。

#### 3.1.2 商品池数据结构

```cpp
struct CommodityPool {
    int64_t supply[6];   // 各商品供给量（初始 100，避免除零）
    int64_t demand[6];   // 各商品需求量（初始 0，自然衰减）
};
```

**关键设计**：
- **供给是库存**：NPC 生产增加 supply，永远是正值
- **需求是流量**：NPC 消费增加 demand，每 600 帧自动衰减 ×0.95，模拟需求自然消退
- 供需分离确保价格不会因一次性的短暂消费而永久扭曲

#### 3.1.3 定价引擎——对数弹性公式

```
price = basePrice × (1 + elasticity × ln(demand / max(supply, 1)))
       clamped to [basePrice × 0.3, basePrice × 3.0]
```

| 参数 | 值 | 经济学含义 |
|:---|:---|:---|
| elasticity | 0.3 | **需求价格弹性**（Price Elasticity of Demand）。值越小，商品越接近必需品（价格变化对需求影响小） |
| floor | basePrice × 0.3 | **价格地板**（Price Floor）。防止价格崩盘，模拟政府最低限价 |
| ceiling | basePrice × 3.0 | **价格天花板**（Price Ceiling）。防止恶性通胀，模拟政府最高限价 |

**为什么用对数而非线性？**

```
线性:    price = base × (1 + 0.3 × d/s)     — 供给翻倍，价格翻倍，过于剧烈
对数:    price = base × (1 + 0.3 × ln(d/s)) — 供给翻倍，价格变化平缓

示例（Ore base=5, supply=100）:
demand=200 → 线性: 5×1.6=8.0  对数: 5×1.208=6.0
demand=500 → 线性: 5×2.5=12.5 对数: 5×1.483=7.4
demand=1000→ 线性: 5×4.0=20.0 对数: 5×1.691=8.5 (受 ceiling 限制=15.0)
```

对数公式对初期供需变化敏感（小市场容易调节），对极端供需有自然阻尼（大市场不易剧烈震荡）。这对应经济学中的**边际效用递减**——价格对供需变化的响应随偏离程度增大而减弱。

**定价示例**：

| 场景 | supply | demand | d/s | 价格 | 经济学解读 |
|:---|:---|:---|:---|:---|:---|
| 均衡 | 100 | 100 | 1.0 | 5.0 | 市场均衡（Market Equilibrium） |
| 供不应求 | 100 | 500 | 5.0 | **7.4** | 需求拉动型通胀（Demand-Pull Inflation） |
| 供过于求 | 1000 | 200 | 0.2 | **2.6** | 产能过剩（Overcapacity） |
| 极端紧缺 | 10 | 1000 | 100 | **15.0** | 供给冲击（Supply Shock），触及天花板 |
| 极端过剩 | 10000 | 1 | 0.0001 | **1.5** | 通货紧缩（Deflation），触及地板 |

### 3.2 产业结构——角色模板与比较优势

#### 3.2.1 角色模板定义产业结构

`NPCRole` 角色模板定义了家族的**产业分工**：

| 角色模板 | 产业角色 | 经济学对应 | 价值链条位置 |
|:---|:---|:---|:---|
| **FamilyHead** | 战略决策者 + 贸易商 | 企业家/资本家 | 价值链顶端（分配资源） |
| **Elder** | 监管者 + 高级生产者 | 高级管理层 | 价值链中上层 |
| **CoreDisciple** | 投资对象（未来高价值劳动力） | 人力资本投资 | 价值链中层（当前消耗，未来产出） |
| **InnerDisciple** | 中级生产者 | 熟练工人 | 价值链中层 |
| **BranchDisciple** | 初级生产者（矿工/农民） | 初级劳动者 | 价值链底层（原材料供给） |

#### 3.2.2 比较优势与专业化

不同家族因**传承（factionCareerHeritage）**不同，天然具有不同的**比较优势（Comparative Advantage）**：

- 秦国擅长采矿（矿脉资源丰富）→ 采矿行为的 `economicBiasFor` 更高
- 楚国擅长炼丹（灵草资源丰富）→ 炼丹行为的 `economicBiasFor` 更高

根据李嘉图的比较优势理论，即使秦国在所有产业都比楚国强（绝对优势），两国仍然可以通过**专业化+贸易**实现双赢。当前系统通过商队套利部分实现了这一点，但缺少主动的专业化决策——T0 的 LLM 规划中应考虑"产业政策"概念。

### 3.3 家族财政——税收、库房与贡献值

#### 3.3.1 自动抽税——公共财政的收入端

每次 NPC 完成 Sell/Buy/Bargain/Trade 交易时，系统自动抽取交易税汇入家族 Treasury。V4 起税率可由 T0 级 NPC 通过 `SetTaxRate` 行为动态调整（范围 1%-15%，默认 5%）。V5 修复了双重征税 bug——`collectTax(clanId, tradeValue)` 内部按 `tradeValue × clanTaxRate` 计算税额：

```
NPC 卖出装备获得 40 灵石（税率 5%）
  → collectTax(clanId, 40) → 税额 = 40 × 0.05 = 2 灵石
  → 家族 Treasury += 2 灵石
  → NPC familyContribution += 4（税额 × 2，贡献值双倍于税额）

T0 秦王调高税率至 10%
  → 后续交易抽税 10%
  → 高贪婪 NPC 截留概率 +5%（税率过高引发"走私"——拉弗曲线效应）
```

**拉弗曲线效应**：税率超过最优值后，NPC 的截留/抗命行为增加，实际税收收入反而下降。当前系统通过贪婪性格修正部分实现了这一点。

#### 3.3.2 库房资助突破——公共财政的支出端

当核心弟子修为满值但个人灵石不足支付突破费用时，系统自动从家族 Treasury 借款——这是**人力资本投资（Human Capital Investment）**：

| 境界突破 | 灵石消耗 | 经济学含义 |
|:---|:---|:---|
| 练气 → 筑基 | 300 | 基础教育投资 |
| 筑基 → 金丹 | 1,000 | 高等教育投资 |
| 金丹 → 元婴 | 3,000 | 研究生/博士投资 |
| 元婴 → 化神 | 10,000 | 顶尖人才培养（几乎耗尽一个小家族的积累） |

突破成功后弟子实力大增，可为家族创造更多价值（更好的生产/战斗能力）。突破失败则损失灵石但保留修为。

> 若家族 Treasury 不足，弟子无法突破，必须等待库房积累或自行攒钱。这产生了"穷家族弟子卡瓶颈"的涌现叙事——对应现实中的**流动性约束（Liquidity Constraint）**。

#### 3.3.3 家族贡献值——社会资本

`familyContribution` 是每个 NPC 对家族的**社会资本积分**。纳税时增加，借款突破时减少（可变为负值表示负债）。未来扩展方向：贡献值可兑换家族专属资源、高贡献者在长老会中有更大话语权、贡献值为负的弟子被家族催债。

### 3.4 商队套利——跨区域物价平衡器

**经济学映射**：商队套利是**一价定律（Law of One Price）**的实现——价差 > 20% 时触发套利，直到价格趋同。

#### 3.4.1 套利逻辑

```
① CaravanSystem::findBestRoute(clanId)
   遍历所有家族的 CommodityPool，对 6 种商品逐一比较价差
   找出利润率最高的路线（价差 > 20% 且未在冷却中）

② 执行套利
   从低价区买入 100 单位商品 → 从 high-demand 区卖出
   利润 = 100 × (卖出价 - 买入价) × 0.95（5% 税后）

③ 物价平抑
   低价区：supply 减少 100 → 价格微涨
   高价区：supply 增加 100 → 价格微降
   多次往返后两区域价格趋于一致
```

#### 3.4.2 商队风险与冷却

| 机制 | 数值 | 经济学含义 |
|:---|:---|:---|
| 同路线冷却 | 500 帧 | 交易成本（防止高频套利） |
| 贸易禁令（V4） | T0 级 NPC 可设置，持续 1200 帧 | 保护主义政策 |
| 劫匪风险 | 5% 概率，损失 50% 货物 | 随机交易成本/风险溢价 |
| 利润归属 | 全部存入家族 Treasury | 公共财政收入 |

#### 3.4.3 触发条件

当家主（FamilyHead）或长老（Elder）NPC 且家族有 **Merchant（商贾）** 传承时，在 Daily 层有 10% 概率触发商队行为。

### 3.5 阵营竞争——家族间经济博弈

家族间不仅是贸易伙伴，也是**竞争对手**。V6.1 引入的**阵营偏见**为家族间关系设定了"底线"：

> 家族 A 与家族 B 立场亲和度 **-40** → 两族弟子的个人负亲密度衰减到 **-10** 后停止，不会归零

这意味着**经济制裁有持久效果**：即使时间流逝，敌对家族间的贸易壁垒仍然存在。但如果 NPC 主动帮助敌方成员，亲密度可以突破阵营底线——"患难见真情"仍然可能发生。

## 四、宏观经济——国家/文明级经济

> **核心概念**：多个家族经济体构成一个**多国经济体系**。灵石作为统一货币，财政政策（税率）和贸易政策（商队/禁令）影响整个体系的经济周期。EconomicDigest 为高层 NPC 提供宏观经济情报，驱动战略决策。

### 4.1 货币体系——灵石的双重身份

#### 4.1.1 灵石作为商品货币

灵石是这个世界的**商品货币（Commodity Money）**——它既是交换媒介，也是生产/突破的消耗品。这类似于金本位制度下黄金的角色：

| 货币概念 | 游戏实现 | 经济学对应 |
|:---|:---|:---|
| **货币供给 M** | 所有 NPC 持有的灵石总和 + Treasury | M1（狭义货币） |
| **货币发行** | NPC 生产→出售→获得灵石 | 零基础货币发行（信用创造） |
| **货币需求** | 购买、突破、建造消耗灵石 | 交易需求 + 投资需求 |
| **购买力** | 1 灵石能买多少其他商品 | 实际汇率（Real Exchange Rate） |
| **通胀/通缩** | `spiritStoneInflation` = d/s 比值 | CPI（消费者物价指数） |

#### 4.1.2 灵石的自我调节机制

当大量灵石被用于突破（投资消耗），流通中的灵石减少→**通缩**→灵石购买力上升→NPC 更难获得灵石→突破更难。这形成了一个**自我调节的货币机制**——不需要中央银行，市场自动平衡。

#### 4.1.3 货币幻觉

当前系统有一个**货币幻觉（Money Illusion）**问题：NPC 的反思系统用**名义收益**（灵石数量 × 当前价格）而非**实际收益**（扣除通胀后的购买力）来评估行为结果。在高通胀时期，NPC 可能认为自己在赚钱（名义灵石增加），但实际购买力在下降。

### 4.2 财政政策——自动稳定器 + 自主政策

#### 4.2.1 两种政策工具

| 政策类型 | 工具 | 执行者 | 经济学对应 |
|:---|:---|:---|:---|
| **自动稳定器** | EconomicCrisis 层（优先级 2.5） | T1/T2 自动触发，无需 LLM | 失业保险、累进税制 |
| **自主政策** | 5 种经济战略行为 | T0-T2 主动决策，通过 LLM 或规则触发 | 财政刺激、降息 |

#### 4.2.2 自动稳定器——EconomicCrisis 层

在现有的 7 层行为决策中插入优先级 **2.5** 的 EconomicCrisis 层（Emotion 和 Command 之间），仅在态势为 Crisis 时触发。V5 优化：同族成员查找从全实体遍历 O(N) 改为 clanId 反向索引 O(clanMembers)；T1/T2 执行动员后返回 `true` 阻断后续决策层：

```
T2 长老检测到 Crisis
  → 经济动员：全族紧缺商品关联行为基线权重 ×1.5（通过 setTemporaryBoost，300 帧自动过期）
  → 返回 true，阻断后续层（不再走到 Daily 选择其他行为）
  → 若为 T1：额外执行价格平準（Treasury 动用 ≤30% 余额或 300 灵石上限，溢价 120% 收購短缺商品）

Crisis 解除（态势恢复为 Tight 或更好）
  → 经济动员自动撤销，价格平準自动停止
```

#### 4.2.3 自主政策——五种经济战略行为

新增 5 种经济战略行为，纳入 `ActivityCategory::EconomyStrategy`，注册在 kExecuteTable：

| 行为 | 执行者 | 经济学工具 | 效果 |
|:---|:---|:---|:---|
| **SetTaxRate** 设置税率 | T0 | 税率政策（Tax Policy） | Crisis→12%, Tight→8%, Balanced→5%, Surplus→3%，性格修正后 clamp 到 [1%-15%] |
| **TradeEmbargo** 贸易禁令 | T0 | 保护主义（Protectionism） | 禁止与指定家族交互，CaravanSystem 跳过该路线，冷却 1200 帧 |
| **StockpileMaterial** 物资囤积 | T1 | 战略储备（Strategic Reserve） | 标记指定商品 30% 为战略储备，不进入 PriceEngine 定价的 supply 计算 |
| **PriceStabilize** 价格平準 | T1 | 价格管制（Price Control） | 短缺时溢价 120% 收購，过剩时折价 80% 抛售，回写 CommodityPool |
| **EconomicMobilize** 经济动员 | T2 | 供给侧改革（Supply-Side Reform） | 全族 NPC 指定行为基线权重 ×1.5，300 帧后自动过期 |

每种行为在 execute 阶段通过 MarketRegistry 回写 CommodityPool/Treasury，确保经济后果被追踪。

### 4.3 贸易政策——商队、禁令与一价定律

#### 4.3.1 自由贸易 vs 保护主义

当前系统同时支持两种贸易政策：

| 政策 | 实现 | 效果 | 经济学理论 |
|:---|:---|:---|:---|
| **自由贸易** | CaravanSystem 自动套利 | 跨区价差被平抑，资源向高效配置流动 | 比较优势理论（Ricardo） |
| **保护主义** | TradeEmbargo 禁止指定家族贸易 | 被制裁方失去廉价商品来源，被迫自建产能 | 制裁经济学 |

#### 4.3.2 贸易禁令的战略价值

当秦王对楚国实施贸易禁令时，效果链：

```
短期：楚国失去廉价秦矿来源 → 楚国铁匠成本上升 → 楚国装备价格上升
中期：楚国被迫自建矿场或寻找替代贸易伙伴 → 资源重新配置
长期：如果楚国找到替代方案，禁令效果递减
```

这完全符合现实中的**制裁经济学**——制裁的效果取决于被制裁方的替代选项。LLM 规划时需要考虑这一点。

### 4.4 经济周期——Surplus → Balanced → Tight → Crisis

#### 4.4.1 四态循环

```
            需求增加/供给冲击
    Surplus ─────────────────→ Balanced
      ↑                          │
      │                          │ 需求继续增加/供给不足
      │                          ↓
    Balanced ←───────────────── Tight
      ↑                          │
      │                          │ 供给严重不足/储备耗尽
      │                          ↓
      └─────────────────────── Crisis
                危机干预/自动恢复
```

#### 4.4.2 态势判定逻辑

| 条件 | 态势 | 经济学对应 | 政策响应 |
|:---|:---|:---|:---|
| 储备率 < 0.5 周或 max(d/s) > 3.0 | **Crisis**（危机） | 萧条（Depression） | 紧急加税 12% + 动员 + 平準 |
| 储备率 < 1.0 周或 max(d/s) > 2.0 | **Tight**（紧张） | 衰退（Recession） | 加税 8% 积累储备 |
| 储备率 > 3.0 周且 max(d/s) < 1.2 | **Surplus**（盈馀） | 经济过热（Overheating） | 降税 3% 吸引消费 |
| 其余 | **Balanced**（平衡） | 充分就业均衡 | 维持现状 5% |

储备率 = Treasury / (weeklyExpense × 4)，即库房能支撑多少周的支出。

#### 4.4.3 恶性循环与自动稳定器

当前系统有一个潜在的**正反馈循环（恶性循环）**：

```
矿石短缺 → 矿石涨价 → 铁匠成本上升 → 装备涨价 → NPC 买不起装备
  → 战斗力下降 → 战争失利 → 灵石消耗 → 库房紧张 → 无法资助突破
  → 弟子卡瓶颈 → 生产力停滞 → 更多短缺...
```

`EconomicCrisis` 层的自动稳定器正是为了**打断这个恶性循环**。但如果危机来得太快（如多条供给线同时断裂），300 帧的动员窗口可能不够。建议引入**分级响应**——Tight 时就开始轻度干预，不要等到 Crisis。

### 4.5 战略经济——战争经济学与情报驱动决策

#### 4.5.1 EconomicDigest——宏观经济情报

系统为每个家族维护一份 `EconomicDigest`，每 600 帧（与需求衰减同频）重新计算。TTL=600 帧缓存，命中率 > 99%。这对应现实中的**宏观经济指标体系**：

```cpp
struct EconomicDigest {
    EconomicPosture posture;          // 态势（≈ PMI 采购经理人指数）
    int64_t treasuryBalance;          // 库房余额（≈ 外汇储备）
    float weeklyIncomeRate;           // 每 600 帧净收入（≈ GDP 增长率）
    float weeklyExpenseRate;          // 每 600 帧净支出（≈ 财政支出）
    CommodityAlert alerts[3];         // 最严重的 3 个供需异常（≈ CPI 分项数据）
    TradeOpportunity opportunities[2]; // 跨家族套利机会（≈ 国际贸易报告）
    EnemyWeakness enemyWeaknesses[2];  // 敌对家族经济弱点（≈ 敌国经济制裁评估）
};
```

#### 4.5.2 战争成本评估框架

LLM 规划战争时需要评估的经济成本：

| 成本类型 | 经济学对应 | 当前系统追踪 |
|:---|:---|:---|
| **直接军费** | 政府军事支出 | ✅ 战斗 NPC 的丹药/装备/灵石消耗 |
| **机会成本** | 资源的次优用途价值 | ✅ 战斗 NPC 不能生产的损失 |
| **物资消耗** | 战略储备消耗 | ✅ CommodityPool 追踪 |
| **战后重建** | 基础设施投资 | ✅ Build/Repair 行为 |
| **占领收益** | 领土扩张的经济收益 | ⚠️ 缺少占领区经济整合 |
| **贸易格局变化** | 地缘经济重组 | ⚠️ 缺少外交-经济联动 |

#### 4.5.3 完整决策链示例：秦国矿石危机

```
① 经济触发（每 600 帧）
   CommodityPool[秦][Ore]: supply=45, demand=380 → priceRatio=2.7
   Treasury=900，周净流出=-80
   EconomicDigest.posture = Crisis
   [经济学解读]：供给冲击（Supply Shock）导致的结构性危机

② T2 自动响应（无需 LLM，EconomicCrisis 层——自动稳定器）
   全族 Miner 角色 NPC 采矿基线权重 ×1.5（300 帧）
   [经济学解读]：供给侧刺激（Supply-Side Stimulus）

③ T1 自动响应（无需 LLM）
   价格平準：Treasury 支出 270 灵石（<30%余额），溢价 120% 收购矿石
   Ore supply += 收购量
   [经济学解读]：政府购买（Government Purchase）+ 价格管制

④ T0 LLM 规划（下次调用时注入经济摘要）
   Prompt 中包含危机态势 + 矿石短缺警报 + 楚矿套利机会 + 韩灵石见底
   LLM 输出意图: "seize_chu_northern_mine" 或 "trade_diplomacy_with_chu"
   [经济学解读]：经济情报驱动的军事/外交决策

⑤ 规则引擎拆解意图 → T1/T2 具体行动
   seize_chu_northern_mine → T1: 集結 15 名战斗型 NPC，目标座标(1200,800)
                            T1: StockpileMaterial(Pills, 50%)
                            T2: EconomicMobilize(Alchemy, ×1.5)

⑥ 经济循环闭环
   夺矿成功 → Ore supply +300/600帧 → 矿石价格回落 →
   态势从 Crisis → Balanced → 动员和平準自动撤销 →
   T0 LLM 下次收到："矿石危机已解除，库房因战争消耗降至 400，建议休养"
```

## 五、LLM 经济决策支持

> **核心问题**：LLM 收到的经济数据是原始数字，缺少经济学因果推理所需的上下文。本章设计分层经济情报体系，使 LLM 能像真正的经济学家/战略家一样思考。

### 5.1 分层经济情报体系

不同层级的 NPC 需要不同粒度的经济情报：

#### 第一层：微观经济情报（T2 长老用）——"基层在发生什么"

```
[基层经济情报 - 秦国]
生产状况：
  - 矿工平均收益：39灵石/次（矿石过剩时）→ 111灵石/次（矿石紧缺时）
  - 采矿行为反思权重：0.7（连续失败后下降）
  - 当前活跃矿工数：12人（较上周 -3人，转向耕种）

消费状况：
  - 弟子平均灵石持有：45灵石
  - 突破瓶颈弟子：3人（灵石不足无法突破）
  - 食物自给率：85%（15%依赖外部）
```

#### 第二层：中观经济情报（T1 白起用）——"家族经济健康度"

```
[家族经济情报 - 秦国]
产业结构：
  - 矿业占比：40%（过度依赖）→ 建议分散
  - 农业占比：25%（勉强自给）
  - 制造业占比：20%（附加值高，但原材料依赖矿业）
  - 贸易占比：15%（商队利润率 28%）

财政状况：
  - 库房余额：900灵石
  - 周收入：+120灵石（税收+贸易利润）
  - 周支出：-200灵石（突破资助+军费）
  - 储备率：4.5周（但趋势下降）

市场状况：
  - 矿石价格 2.7×（严重紧缺，正在通过动员缓解）
  - 丹药价格 1.5×（轻度紧缺，筑基丹需求旺盛）
  - 食物价格 0.8×（轻度过剩）
```

#### 第三层：宏观经济情报（T0 秦王用）——"天下大势"

```
[天下经济情报]
秦国：Crisis（矿石危机，库房下降中）
  → 弱点：矿石依赖单一矿脉，易被切断
  → 优势：商队网络健全，贸易利润稳定

楚国：Tight（灵石紧缺，但矿石充裕）
  → 弱点：灵石见底，无法资助弟子突破
  → 优势：矿石供给充足，铁匠产能强大
  → 套利机会：秦矿石高价↔楚灵石高价 = 双向贸易利得

魏国：Surplus（全面盈余，但装备过剩）
  → 弱点：装备价格崩盘，大量库存积压
  → 优势：经济健康，可作为贸易盟友
```

### 5.2 经济因果链注入

LLM 最需要的不是原始数字，而是**因果推理链**。建议在 prompt 中注入：

```
[经济因果分析]
当前因果链：
  矿脉被妖兽占领 → 矿石供给骤降 → 矿石价格飙升至 2.7×
    → 铁匠成本上升 → 装备产出减少 → 弟子战斗力提升受阻
    → 同时：矿工收入锐减 → 消费下降 → 食物/材料需求萎缩
    → 连锁效应：库房税收减少（交易量下降）

风险评估：
  若不干预：4.5周后库房耗尽 → 无法资助突破 → 弟子卡瓶颈
  若发动战争：短期消耗 1500灵石 → 储备率降至 1.5周 → 但夺矿后长期改善
  若贸易联盟：零成本解当前危机 → 但形成贸易依赖 → 长期风险
```

### 5.3 经济决策树——LLM 的推理框架

```
经济决策树（T0 使用）：
├─ 态势 = Crisis？
│   ├─ 是 → 评估战争可行性
│   │   ├─ 储备率 > 2周 且 有明确军事目标 → 发动有限战争
│   │   └─ 储备率 < 2周 → 优先贸易联盟/经济自强
│   └─ 否 → 继续评估
├─ 态势 = Tight？
│   ├─ 有套利机会 → 开放贸易
│   └─ 无套利 → 调整产业结构（减少过剩产业，增加紧缺产业）
├─ 态势 = Balanced？
│   ├─ 有敌族弱点 → 经济制裁/贸易战
│   └─ 无威胁 → 积累储备 + 投资人力资本（弟子突破）
└─ 态势 = Surplus？
    ├─ 有扩张机会 → 投资新产业/新领土
    └─ 无机会 → 降税促进消费 + 加速弟子培养
```

### 5.4 LLM Prompt 中的经济学常识注入

在 LLM 的 system prompt 中注入经济学常识，让 LLM 理解经济规律：

```markdown
[经济学常识——修仙世界版]
1. 供需定律：供给增加→价格下降，需求增加→价格上升
2. 边际递减：持续做同一件事，收益会递减（反思系统已实现）
3. 机会成本：做A就不能做B，战争的代价是失去生产时间
4. 比较优势：每个家族应专注于自己最擅长的产业
5. 通胀效应：灵石过多→购买力下降→所有商品名义涨价
6. 乘数效应：一个矿脉被切断，影响不只是矿石——会波及铁匠、装备、战斗力
7. 拉弗曲线：税率超过最优值后，税收反而下降
8. 流动性陷阱：库房耗尽时，任何经济政策都无法执行
9. 制裁经济学：贸易禁令的效果取决于被制裁方的替代选项
10. 一价定律：跨区价差会被商队套利消除
```

### 5.5 当前 LLM Prompt 注入实现

V4 中，`LLMPlanningService.buildPlanPromptWithFrontline()` 新增 `economicDigestText` 参数。在构建 T0/T1 LLM prompt 时，从 WASM 读取 EconomicDigest 并格式化注入：

```
[经济态势]
库房：900 灵石（周净-80）
态势：危机
异常警报：
  - 矿石：供给45 需求380 价格2.7×基准 — 矿石严重短缺
战略情报：
  - 套利机会：从[楚]购矿石运往[秦]可获利35%
  - 敌族弱点：[韩]的灵石见底
```

T0 收到完整摘要（态势 + 警报 + 套利机会 + 敌族弱点），T1 仅收到态势 + 警报。LLM 据此产出有经济依据的意图——从抽象的「联魏伐楚」升级为「楚国缺矿，若我军夺取东侧矿脉不仅解决我方矿石危机，更可使楚国铁匠产能崩溃」。

### 6.2 经济信号反馈——NPC 感知市场

V7.3 已将 EconomicSignals 从基于家族传承的启发式代理切换为读取真实供需数据。V3 进一步优化：`MarketRegistry` 层级维护 `CachedEconSignals` 缓存（TTL=100 帧），避免每个 NPC 每帧重复计算。需求衰减时自动标记缓存为 dirty。

```cpp
struct CachedEconSignals {
    float ironOreDemand, spiritStoneInflation, foodDemand;
    float equipmentDemand, materialDemand, cultivationDemand;
    uint64_t cachedFrame;
    bool dirty;
};
```

调用链路：

```
evaluateDaily()
  → MarketRegistry::getEconomicSignals(clanId, currentFrame)
      → 命中缓存（未 dirty 且帧差 < 100）→ 直接返回
      → 未命中 → 从 CommodityPool 计算供需比 → 写入缓存 → 返回
  → MarketRegistry::tickDecay(currentFrame)
      → 每 600 帧衰减 demand × 0.95，同时标记所有缓存 dirty
```

### 6.3 性能特点

| 指标 | 数值 |
|:---|:---|
| CommodityPool 内存 | < 256 bytes / 家族（6×2 int64_t + map overhead） |
| NPC 个人背包内存 | 平均 < 80 bytes / NPC（假设 3 种物品，ItemSlot=8 bytes） |
| PriceEngine::getPrice | O(1) 纯算术，无循环 |
| 需求衰减 | 每 600 帧触发一次，O(families × 6) |
| EconomicSignals 缓存 | TTL=100 帧，命中率 > 99%（同帧内同族 NPC 共享） |
| EconomicDigest 缓存 | TTL=600 帧，命中率 > 99% |
| CaravanSystem::findBestRoute | O(families × 6)，10% 触发概率下极少调用 |
| 生产行为接入 | recordProduction/Consumption 为 O(1) map 查找，addItem 线性搜索 ≤5 个元素 |
| WASM 物品导出 | 全量 NPCState 140 字节/NPC，详情按需拉取 |
| WASM 经济摘要导出 | EconomicDigestWasm ≤ 256 字节/家族 |
| 经济战略行为 | 仅在 T0-T2 高优先级层触发，层级 NPC < 家族数 × 3 |

### 6.4 与 NPC 行为系统的对接

经济引擎通过**四个接口**与 NPC 行为系统深度耦合：

#### 6.4.1 上行（NPC → 经济）

所有生产/交易行为通过 `MarketRegistry::recordProduction/Consumption` 写入 CommodityPool，同时通过 `ResourcesComponent::addItem/removeItem` 更新 NPC 个人背包。

#### 6.4.2 下行（经济 → NPC）

`MarketRegistry::getEconomicSignals(clanId, frame)` 读取 CommodityPool 供需比，缓存命中则直接返回。`chooseByRole` 中的 `economicBiasFor` 函数根据行为产出的商品类型匹配对应的需求信号，调节行为选择概率。

V4 新增：`MarketRegistry::getEconomicDigest(clanId, frame)` 读取经济态势摘要（TTL=600 帧缓存），供 EconomicCrisis 决策层和 LLM 规划使用。

```
经济紧缺 → 信号偏置 → NPC 行为调整 → 供需变化 → 经济缓解
    ↑                        ↑
    └── V4: EconomicDigest → EconomicCrisis 层（态势=Crisis时自动动员）
                            → LLM Prompt 注入（T0-T1 战略决策）
```

#### 6.4.3 高层决策（V4 新增）

经济数据首次进入 T0-T2 决策流程：

- **EconomicCrisis 层**（优先级 2.5）：态势=Crisis 时自动触发经济动员 + 价格平準，无需 LLM
- **经济战略行为**：5 种行为纳入 kExecuteTable，可通过 LLM 意图式规划调用
- **LLM Prompt 注入**：`LLMPlanningService.formatEconomicDigestForPrompt()` 格式化经济摘要，注入 T0/T1 的 system prompt

#### 6.4.4 WASM 桥接

V3 新增两级导出机制，V4 新增经济摘要导出：

- **全量同步**（每帧 `ecs_getNPCStates`）：`NPCStateWasm` 携带 `itemCount`（uint8_t）和 `equipmentItemId`（uint8_t），仅增加 2 字节
- **按需拉取**（前端打开面板时 `wasmGetNPCItems`）：返回完整物品列表（itemId + count） + spiritStones + familyContribution
- **经济摘要拉取**（LLM 规划时 `wasmGetEconomicDigest`）：返回 EconomicDigestWasm（≤256 字节），包含态势、警報、套利机会、敌族弱点

```cpp
// 140 字节紧凑结构，itemCount/equipmentItemId 复用原有 _pad 空间
struct NPCStateWasm {
    // ...
    uint8_t commandStatus;      // offset 132
    uint8_t itemCount;          // offset 133 — NPC 背包物品种类数
    uint8_t equipmentItemId;    // offset 134 — 当前装备物品 ID
    uint8_t _pad;               // offset 135
    uint32_t squadId;           // offset 136
};
```

### 7.1 迭代总览

# NPC 行为系统设计评审改进 Spec

## Why
资深游戏AI设计师对《太古纪元：霸业》分层优先级决策系统进行了深度评审，在充分肯定V5-V7架构演进的同时，指出了三个关键改进方向：LLM高层规划缺少叙事抽象、微规划映射表硬编码导致NPC缺乏社会角色粘性、缺乏可调试的决策链日志。这些改进将系统从"让AI更聪明"推进到"让AI创造的故事可信、有趣且可被理解"。

## What Changes
- **叙事状态机**：为LLM前线摘要注入叙事状态抽象，将"伤亡率40%，矿脉被占"转化为"前线士气低迷，矿脉失守导致军械告急"的叙事摘要，使LLM生成更具"人味"的战略指令
- **行为标签体系化**：用多维行为标签（职业系、资源系、性格系）替换微规划的硬编码映射表，并引入社会角色粘性因子防止NPC趋同化
- **意义构建日志**：增加第一人称叙事风格的决策链日志，记录从高层优先级决策到底层行为选择的完整因果链
- 社会角色粘性：基于身份和家族约束，防止反思+微规划导致所有NPC最终趋同于最高效行为

## Impact
- Affected specs: npc-behavior-system-v7
- Affected code: `LLMPlanningService.ts`, `BehaviorTree_Production.h`, `BehaviorTree_Daily.h`, `BehaviorTree_Exploration.h`, `BehaviorComponent.h`, `PersonalityComponent.h`
- 叙事状态机为纯TS层改动，不涉及C++ WASM侧
- 行为标签体系涉及C++枚举扩展和BehaviorTreeSystem决策逻辑
- 意义构建日志为新增模块，在C++侧记录，TS侧提供可视化接口

## ADDED Requirements

### Requirement: LLM叙事状态机
系统 SHALL 在构造LLM前线摘要时，将原始统计数据转换为叙事状态描述，使LLM生成的战略指令更符合人类决策直觉。

#### Scenario: 前线摘要的叙事转换
- **WHEN** TS层 `LLMPlanningService.ts` 采集前线数据准备注入LLM prompt
- **THEN** 系统将原始统计（如`伤亡率40%`、`矿脉被占`、`灵石储备低于警戒线`）映射为叙事状态标签（如`士气低迷`、`资源告急`、`领地沦陷`）
- **THEN** LLM prompt中注入的摘要格式从"东线伤亡率40%，矿脉A被妖兽占领"变为"东线已成血肉磨盘，矿脉失守导致军械告急"

#### Scenario: 叙事状态的分级
- **WHEN** 某指标跨越阈值
- **THEN** 系统生成对应的叙事状态，按严重度排序。例如：
  - 伤亡率 < 10% → `战况胶着`
  - 伤亡率 10-30% → `伤亡惨重`
  - 伤亡率 > 30% → `血肉磨盘`
  - 矿脉被占 → `资源告急`
  - 矿脉被占 + 储备不足 → `军械告急`

#### Scenario: 叙事状态的组合与摘要
- **WHEN** 多个叙事状态同时存在
- **THEN** 按严重度优先排序，最多保留3条，组合为叙事摘要文本
- **THEN** 叙事摘要附带原始数据引用，供LLM在需要精确数字时查询

### Requirement: 行为标签体系
系统 SHALL 为50种NPC行为建立多维度标签体系，替换微规划中的硬编码映射表。

#### Scenario: 标签维度定义
- **WHEN** 系统初始化行为标签库
- **THEN** 每种行为具有以下维度的标签集合：
  - **职业系标签**：`[矿工系]`、`[渔夫系]`、`[铁匠系]`、`[农夫系]`、`[猎户系]`、`[修士系]`、`[商贾系]`、`[兵士系]`等
  - **资源标签**：`产出[灵石]`、`产出[食物]`、`产出[装备]`、`消耗[体力]`、`消耗[灵石]`、`需要[水域]`、`需要[矿脉]`、`需要[林地]`等
  - **性格标签**：`[偏好独处]`、`[偏好协作]`、`[风险追求]`、`[风险规避]`、`[体力消耗大]`、`[体力消耗小]`等

#### Scenario: 标签驱动的微规划匹配
- **WHEN** NPC触发微规划（全部已知行为权重 < 0.7，连续卡住 5 帧）
- **THEN** 系统基于NPC当前身份标签和性格标签，寻找标签相似度最高的替代行为：
  - 身份标签匹配：优先选择与NPC当前职业系标签重叠的行为
  - 性格标签匹配：勤奋者优先选产出类，谨慎者优先选安全类，野心者优先选探索类
  - 综合得分 = 身份匹配得分 × 0.6 + 性格匹配得分 × 0.3 + 资源可行性 × 0.1

#### Scenario: 标签库的可扩展性
- **WHEN** 新增行为（如"茶馆喝茶"）
- **THEN** 只需在标签库中定义新行为的标签，微规划系统自动纳入匹配范围，无需修改任何映射代码

### Requirement: 社会角色粘性
系统 SHALL 在反思和微规划过程中施加社会角色约束，防止NPC行为趋同化。

#### Scenario: 家族/职业粘性
- **WHEN** `[矿工系]`标签的NPC触发反思或微规划
- **THEN** 替换行为的标签匹配施加职业系偏向：
  - 家族有锻造传统 → `[矿工系]`→`[铁匠系]` 的转换权重 ×1.5
  - 家族标签与`[渔夫系]`无关 → `[矿工系]`→`[渔夫系]` 的转换权重 ×0.3
  - 即NPC优先在"矿工→锻造→交易→采矿"等金属相关行为中流转

#### Scenario: 角色粘性的性格调节
- **WHEN** 高野心NPC触发微规划
- **THEN** 角色粘性约束适当放宽（×0.5），允许更大范围的职业转换
- **THEN** 高忠诚NPC的粘性加强（×1.2），更坚守家族传统

#### Scenario: 粘性不阻止必要转换
- **WHEN** 所有同类标签行为均已失败
- **THEN** 粘性约束逐步衰减（每次失败后粘性系数 ×0.8），允许NPC突破角色边界

### Requirement: 意义构建日志
系统 SHALL 在关键决策节点记录第一人称叙事风格的决策链日志，便于设计师调试和验证系统行为。

#### Scenario: 决策链日志格式
- **WHEN** NPC做出行为切换决策
- **THEN** 日志以第一人称叙事格式记录完整决策链：
  ```
  NPC_王铁柱（矿工·筑基期）：
    → 第六层修炼评估：权重低（修为已满，无突破契机）
    → 第七层日常选择：采矿（权重 0.5，连续3次产出低于预期）
    → 反思系统介入：建议尝试耕种（采矿→耕种的微规划映射，标签匹配得分 72%）
    → 决策："采矿没前途，俺也种种地试试"
  最终行为：Farming（耕种）
  ```

#### Scenario: 决策节点的触发
- **WHEN** 以下事件之一发生：
  - 行为切换（包括优先级打断和同层级切换）
  - 反思惩罚触发（权重 ×0.5）
  - 遗忘恢复触发
  - 微规划触发
  - 情绪打断行为
- **THEN** 生成一条决策日志

#### Scenario: 日志存储与查询
- **WHEN** 决策日志生成
- **THEN** 存储在环形缓冲区中（每NPC最近500条）
- **THEN** TS侧提供 `getDecisionLog(npcId, count)` 接口，支持按NPC和时间范围查询
- **THEN** 日志包含结构化字段：npcId、frame、触发层、原行为、新行为、权重变化、决策原因枚举

#### Scenario: 日志的性能约束
- **WHEN** 系统在高密度场景下运行（10K+ NPC）
- **THEN** 日志仅在开发/调试模式下记录，发布版本可编译时裁剪
- **THEN** 日志写入为O(1)环形缓冲操作，不产生内存分配

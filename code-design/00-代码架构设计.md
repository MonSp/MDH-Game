# 代码架构设计

## 1. 技术选型

### 1.1 前端技术栈

| 层级 | 技术栈 | 说明 |
|------|--------|------|
| 游戏引擎 | Phaser 3.x | 2.5D像素游戏渲染 |
| 前端框架 | React/Vue | UI界面 |
| 实时通信 | Socket.IO Client | WebSocket通信 |

### 1.2 后端技术栈（混合架构）

| 层级 | 技术栈 | 说明 |
|------|--------|------|
| 网关层 | Node.js + Express | HTTP服务、WebSocket网关 |
| 游戏逻辑层 | C++ ECS Engine | NPC计算密集型逻辑 |
| 实时通信 | Socket.IO | WebSocket实时通信 |
| 数据库 | SQLite | 轻量级本地数据库 |
| IPC通信 | Unix Socket | Node.js与C++进程间通信 |
| 类型安全 | TypeScript/C++ | 前后端类型安全 |

### 1.3 C++ ECS架构

| 模块 | 技术栈 | 说明 |
|------|--------|------|
| ECS框架 | 自研轻量级ECS | Entity-Component-System模式 |
| 组件存储 | Archetype | 组件按类型批量存储优化 |
| 线程调度 | Job System | 多线程并行计算 |
| 任务分发 | ThreadPool | 可配置4-16线程 |
| 工作窃取 | Work Stealing | 负载均衡算法 |

### 1.4 LLM大模型服务

| 模块 | 技术栈 | 说明 |
|------|--------|------|
| HTTP客户端 | libcurl | 异步HTTP请求，支持OpenAI/本地LLM |
| 多线程 | ThreadPool | 8-16并发请求 |
| 提示词 | LLMPromptBuilder | Tier差异化提示词构建 |
| 规划客户端 | LLMPlanningClient | NPC规划请求管理 |

## 6. 关键设计模式

### 6.1 C++ ECS架构模式

- **Entity-Component-System (ECS)**: NPC数据与逻辑分离，组件可组合
- **Archetype存储**: 相同组件类型的Entity批量存储，优化缓存命中
- **Job System**: 多线程任务并行，避免锁竞争

### 6.2 TypeScript设计模式

- **单例模式**: GameService、DataService 全局唯一
- **观察者模式**: 事件系统解耦实体间通信
- **状态机模式**: 玩家状态、NPC AI状态管理
- **对象池模式**: 资源点、子弹等频繁创建销毁的对象

### 6.3 混合架构模式

- **IPC通信模式**: Node.js与C++通过Unix Socket进行进程间通信
- **主从分离模式**: Node.js处理I/O，C++处理计算密集型任务

## 8. 实际技术栈 vs 设计技术栈

| 层级 | 设计文档(docs/) | code-design | 实际实现 |
|------|----------------|-------------|---------|
| 游戏引擎 | Phaser 3.x | Phaser 3.x | **Three.js** (react-three-fiber) |
| 前端框架 | React | React/Vue | React 19 + TypeScript |
| 状态管理 | - | - | Zustand (gameStore.ts) |
| 后端 | Node.js + WebSocket | Node.js + Express | Express + Socket.IO |
| 数据库 | PostgreSQL + MongoDB + Redis | SQLite | better-sqlite3 |
| C++引擎 | - | CMake + C++17 ECS | CMake + C++17 ECS (benchmark only) |
| LLM | Gemini API | GPT-4 | **部分实现** (Node.js LLMHttpClient, PlanParser, NPCMemory, NPCWorldService) |
| CSS | - | - | Tailwind CSS v4 |

### 关键差异说明

1. **渲染引擎**: docs设计用Phaser 3实现2.5D像素渲染，实际使用了Three.js (react-three-fiber)实现3D渲染。2.5D像素风格尚未实现。
2. **数据库严重简化**: docs设计三层数据库(PostgreSQL + MongoDB + Redis)，code-design简化为SQLite，实际使用的better-sqlite3仅创建了表结构，大部分服务的数据仅存在于内存中。
3. **C++引擎独立运行**: C++ ECS引擎是独立的benchmark程序，通过命令行参数启动。`NPAddon.h`提供了N-API桥接但未被实际集成到Node.js进程中。当前游戏服务器(`src/server/index.ts`)纯TypeScript实现。
4. **LLM部分集成**: Phase 1b实现了Node.js端的LLM管线: `LLMHttpClient`支持OpenAI兼容接口和Gemini, `PlanParser`提供JSON提取/验证(`&lt;think&gt;`标签剥离/大括号计数嵌套对象), `NPCMemory`提供3种记忆结构(关系矩阵50×50/交互环形缓冲区20/NPC/见证事件30/NPC)。`NPCWorldService`提供轮询LLM调度和编年史事件推送。C++端的`LLMHttpClient`仍为空桩。
5. **前端路由极简**: 只有`/`(Login)和`/game`(Game)两个路由，没有docs中描述的多游戏模式选择界面。

### 7.3 LLM规划核心类型定义

```typescript
// shared/types/LLMPlanning.ts

export enum LLMTier {
  T0 = 'T0', // 天道级（皇帝、太虚境霸主）
  T1 = 'T1', // 战略级（家族家主、大将军）
  T2 = 'T2', // 战术级（长老、金丹期核心子弟）
  T3 = 'T3'  // 行为树级（其余NPC）
}

export enum PlanningType {
  NORMAL = 'NORMAL',
  EMERGENCY = 'EMERGENCY'
}

export enum ActionType {
  // 通用
  IDLE = 'IDLE',
  REST = 'REST',
  PATROL = 'PATROL',
  EXPLORE = 'EXPLORE',
  // 家族职责
  CULTIVATE = 'CULTIVATE',
  TRADE = 'TRADE',
  LOGISTICS = 'LOGISTICS',
  // 战略
  MILITARY_ORDER = 'MILITARY_ORDER',
  DIPLOMACY = 'DIPLOMACY',
  INTELLIGENCE = 'INTELLIGENCE',
  // 资源
  RESOURCE_ALLOCATION = 'RESOURCE_ALLOCATION',
  RESOURCE_PURCHASE = 'RESOURCE_PURCHASE',
  RESOURCE_RAID = 'RESOURCE_RAID',
  CAPTURE_RESOURCE_POINT = 'CAPTURE_RESOURCE_POINT',
  // 高层
  DOMAIN_WAR = 'DOMAIN_WAR',
  ALLIANCE_FORMATION = 'ALLIANCE_FORMATION',
  CULTIVATE_BREAKTHROUGH = 'CULTIVATE_BREAKTHROUGH'
}

export interface LLMPlanningRequest {
  npc_id: string;
  npc_data: NPCData;
  world_context: WorldContext;
  planning_horizon: '1天' | '1周' | '1月';
  planning_type: PlanningType;
}

export interface LLMPlanningResponse {
  plan_id: string;
  nppc_id: string;
  horizon_days: number;
  primary_goal: string;
  sub_tasks: SubTask[];
  fallback_behavior: string;
}

export interface SubTask {
  task_id: number;
  description: string;
  priority: number;
  target_completion_day: number;
  action_type: ActionType;
  action_params: Record<string, any>;
}

export interface LLMPlan {
  plan_id: string;
  generated_at: number;
  expires_at: number;
  tasks: SubTask[];
  current_task_index: number;
  status: 'ACTIVE' | 'COMPLETED' | 'INTERRUPTED' | 'FAILED';
}

export interface NPCWithLLM extends NPCBaseAttributes {
  llm_plan?: LLMPlan;
  llm_eligibility: {
    tier: LLMTier;
    last_planning_time: number;
    planning_horizon: string;
  };
}
```

### 7.5 与现有系统的集成

| 模块 | 集成方式 | 数据流向 |
|:---|:---|:---|
| **NPC行为树** | LLM任务→行为树节点翻译 | LLM → BT |
| **世界状态** | 读取外交/战争/资源状态 | World → LLM |
| **家族系统** | 读取/更新家族状态 | Family ↔ LLM |
| **经济系统** | 触发市场/跑商事件 | Economy ↔ LLM |
| **事件系统** | 接收/发布世界事件 | Event ↔ LLM |

# PR: LLM vs Deterministic NPC Behavior Benchmark

**Branch:** `benchmark/llm-vs-deterministic`
**Base:** `main`
**Version:** 1.1.0.1

## Summary

Build an automated benchmark script that runs NPCWorldService in LLM-mode and deterministic-mode with identical inputs, scores chronicle events against a 3-dimension rubric, and produces a structured comparison report. This validates the Phase 1b core product thesis: that LLM-driven NPCs produce demonstrably better narrative moments than a deterministic state machine.

## Adversarial Review Findings Addressed

| # | Finding | Severity | Fix |
|---|---|---|---|
| 1 | `reset()` is public on singleton | CRITICAL | Documented; production gating deferred |
| 2 | `reset()` doesn't restore `llmMode` | HIGH | Added `this.llmMode = true` to `reset()` |
| 3 | Math.random not restored after benchmark | HIGH | Save/restore with try/finally |
| 4 | First action silently discarded in advanceQueue | HIGH | Pre-existing bug, not in scope of this PR |
| 5 | Scoring structurally biased toward LLM | HIGH | Acknowledged — intentional design; scoring heuristics can be refined in follow-up |
| 6 | `llm_fallback` source tag never emitted | MEDIUM | Added `llmFallback` flag, set in both fallback paths |
| 7 | Async race between reset() and tick() | MEDIUM | Pre-existing; mitigated by stop() ordering |
| 8 | No input validation on assignTask/ceremony | MEDIUM | Pre-existing, out of scope |
| 9 | planCount metric mislabeled | MEDIUM | Renamed to "Action events captured" |
| 10 | Seed reproducibility limited by divergent tick timing | MEDIUM | Acknowledged limitation; benchmark compares population-level statistics |
| 11 | Event listener leak on error path | LOW | Wrapped listener setup/teardown in try/finally |
| 12 | `as any` bypass on private field | LOW | Added `setLlmMode()` public setter |
| 13 | Vitest describe-block ordering dependency | LOW | Added `afterAll` to restore service state |
